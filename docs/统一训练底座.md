# 统一训练底座

`scripts/experiment.py` 是新实验的统一入口。旧脚本继续可用于复现实验。模型放在
`qkd_rl/model_zoo/<模型名>/`，至少提供 `model.py` 和 `config.yaml`；需要定制观察图时，
在该目录实现 `graph_builder_class()`。`model.py` 提供
`build_model(action_space, config)`。v2 和 v3 均已有独立的模型、构图与配置。

配置按以下顺序合并：现有默认环境与训练 profile → `configs/experiment_base.yaml`
→ 模型目录的 `config.yaml` → 命令行重复提供的 `--config`。种子、更新数和归档路径
最后设置。完整配置保存为每次运行的 `experiment_config.yaml`，训练入口另保存
`resolved_config.yaml`。模型可以只覆盖与自身有关的配置，其余复用公共配置。

```bash
# v3：八天启发式 BC 热启动，然后训练 20 次更新并验证
python scripts/experiment.py train --model v3 --seed 42 --updates 20 --bc --evaluate

# 不做 BC，比较同种子 v2/v3，最多两个任务并行
python scripts/experiment.py batch --models v2 v3 --seeds 42 43 \
  --updates 20 --parallel 2 --evaluate

# 单独评估已有运行；也可以 batch-evaluate --runs <多个目录> --parallel 2
python scripts/experiment.py evaluate --run outputs/experiments/v3/s42
```

输出按 `outputs/experiments/<模型>/<运行名>/` 归档。目录内有配置、运行状态
`manifest.json`、训练日志和 checkpoint；BC 产物在 `bc/`；验证结果在
`validation.json`，其中保留逐种子成功率、秘钥生成和服务量。相同模型与种子的
批量运行共用同一目录，已完成的目录默认拒绝覆盖；续训需显式传 `--resume`。
`manifest.json` 同时记录模型源文件与解析配置的 SHA-256，方便核对后续代码改动。

公共默认值用于快速对比：240 步 rollout、8 个 rollout worker、16 个主进程
PyTorch 线程、PPO batch chunk 16、BC 8 个训练日。`--config` 可覆盖这些值。
批量任务中的 `--parallel` 控制同时运行的任务数，每个任务都将线程预算写入
归档。启动批量前，应按服务器可用内存设置并行数。启发式 BC 预收集数据目前
只包含 v2 观察字段；v3 请使用在线 BC。

目前 v3 配置启用候选边查询的 pair-path attention、端点身份编码与最多 4 hop
路径。v3.1 的第二阶段仍在模型研究中，不把未完成的阶段配置伪装成可训练模型。

已有的旧训练命令不传 `experiment.model` 时仍调用原始模型和构图实现，以保证
旧实验复现不被新目录接口改变。新模型接入时，训练、rollout worker、BC、验证
都通过同一模型接口构造对象。
