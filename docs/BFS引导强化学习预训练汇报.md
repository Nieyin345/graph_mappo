# 用 BFS 中继扩散的启发式策略，给强化学习做预训练

## 1. 我们想解决什么问题

这个任务里，智能体每个时隙要在整个网络里给每个节点挑一条密钥生成链路（每个节点一个发射端、一个接收端，双向都可以，但不能同时冲突），让生成的密钥通过可信中继去喂地面站之间不断冒出来的需求（这些需求有截止时间，过期就浪费）。

问题是：直接从零开始跑强化学习（Graph-MAPPO），起步阶段完全靠乱猜，探索又慢又浪费。所以我们想到一个更聪明的做法——**先让一个"懂行"的专家带着智能体跑一遍，把它的"想法"教给模型，再让模型继续自己练**。这就是常见的预训练 / 行为克隆。

## 2. 我们的专家是谁：BFS 中继扩散 + 贪心匹配

专家用的是一个叫 `GreedyRelayDiffusionPolicyV3` 的规则策略。它做事的逻辑其实很简单，分两步：

### 第一步：给每一条链路打分

对网络里每一条能用的物理链路，算一个分，分数越高越值得激活。这个分主要是看这么几件事：

- **链路快不快**（rate）：速率高的链路更吃香，密钥产得多；
- **这条链路有多"重要"**（importance）：它是不是正卡在好多待办需求的中继路径上，这个就是 BFS 算出来的；
- **能不能"拼一把"**（completion）：假如某条需求的路径上，一半已经有库存了，就差你这半边，那你这半边就特别值钱，要奖励；
- **要不要保持**（keep）：上一时刻就在用的链路，如果还在服务需求，最好继续用，别乱动；
- **切换要扣钱**（switch）：换链路是有代价的（FSO 物理切换），所以新开的链路要稍微惩罚一下。

### 第二步：这个"重要性"到底怎么算（BFS 起作用的点）

BFS 是这么用的：对每一个还没被满足的需求，拿它**两端的那个地面站**各当起点，在网络拓扑上用广度优先搜索 BFS 跑一遍，就知道从这两个站点到网上每个节点各要跳几跳。

然后把每一条物理链路摆进来看：这条链路如果被激活，它能把需求从源站到目的站的路径缩成几跳。只要这个总跳数不超过限制（默认 3 跳），就认为它对这条需求"有用"，把需求的量、紧急程度（等得越久越急）、以及这条链路当前快被用空的程度一起乘进它的重要性里。

最后把整条链路的五项加起来，就得到总分，去喂给贪心匹配。

### 第三步：按分贪心选链路

分排好序之后，从高到低一条条拿，但要守住物理约束：一个节点最多一个发射端出去、最多一个接收端进来、同一条边同一时刻不能两个方向同时开。最后输出的动作格式（双端口）跟在线强化学习一模一样，保证预训练和真正跑 RL 时决策结构对得上。

## 3. 预训练具体是干嘛的（supervised_train_bfs_greedy.py）

专家每走一步，不光告诉我们它选了哪条链路，还把它给**每一条链路打的分**都存下来。然后我们就训练 actor 模型去"模仿专家打的分"——不是死背它选了啥，而是学它那一套"为什么选这条、为什么留下、为什么不要"的判断。

损失函数很简单，就是**预测的分和专家打的分做均方误差**（MSE）：
```
L = 平均e ( 模型打的e的分 − 专家打的e的分 )²
```

再往外一层就是流水线：在设定的激活窗口上让专家跑完整段轨迹，一步一步收集"观测 → 专家全边评分"的标签，喂给模型更新，最后存成一个预训练权重 `supervised_bfs_greedy.pt`。

## 4. 预训练完怎么接强化学习

预训练产出的 checkpoint 就成了 actor 的**初始权重**，我们把这个权重加载进去，接着跑真正的强化学习：

```
python scripts/rl/supervised_train_bfs_greedy.py --run-name supervised_bfs   # 1. 先预训练
python scripts/rl/train_graph_mappo.py --checkpoint outputs/supervised_bfs/supervised_bfs_greedy.pt  # 2. 再续跑RL
```

好处有三点：

- **起步更聪明**：模型一开始就懂"快链路优先、重要链路优先、能保持就别乱切"这些道理，不用从零乱撞；
- **学的东西能接着用**：我们让专家输出和在线 RL 完全相同的动作格式，监督信号正好落在模型真正的打分输出上，接续起来没有断层；
- **可复现**：预训练就在固定的验证窗口和固定种子上跑，环境配置都能原样复现，方便后续对比。

## 5. 怎么跑

```
# 基本预训练
python scripts/rl/supervised_train_bfs_greedy.py --run-name supervised_bfs

# 覆盖窗口每一天 + 从旧权重续训
python scripts/rl/supervised_train_bfs_greedy.py --cover-all-days true --checkpoint outputs/old/supervised_bfs_greedy.pt
```

## 6. 一句话总结

我们先用一个擅长 BFS 中继扩散 + 贪心匹配的专家策略，在全线上跑出高质量的轨迹，让强化学习模型先"跟师傅学打分"，学完这份预训练权重当作起点再去自己练，既省了冷启动的摸索，又保证了和最终 RL 的任务结构完全一致。说白了就是——**给强化学习一个靠谱的起跑线**。
