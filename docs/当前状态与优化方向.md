## 2. 已定案 / 已否决（不要再走）

> 原始数字与推导都在 [`训练诊断记录.md`](训练诊断记录.md) 与
> [`定稿结论.md`](定稿结论.md)。这里只留一行结论。

**硬结论（有 n≥5 或 15/15 证据）**

- BC 暖启动必须保留：从零训 −12.1 点、方差 10.5×
- `demand_edge` 模式显著更差：−0.0527，p=0.0003，15/15 同向
- BC 不是越久越好：ep32 优于 ep60（12/15 下降）⟹ 起 RL 用 ep-32 快照
- 终止语义保持 `terminated`：改 `truncated` 实测 −0.0399，已回滚
- `max_weight_matching` 解码与 PPO on-policy 冲突（30–40 h/臂），不用
- 删 Stockholm 是环境修正：专家 0.6979→0.7674（15/15），旧环境臂不可比

**关闭的线索（测不出 / 前提倒塌）**

- urgency 加权等待惩罚：n=5 剂量单调是假象，n=14 效应消失（Δ=+0.0044，t=+0.87）
- 「让模型看见需求」四连败：demand_edge / v1 / v2 / DemandResidual 均测不出
- `entropy_coef` 线索：n=5「超专家」被节点混淆解释（+0.0197 硬件偏置），正式关闭
- 降 critic_lr、lr 退火、epochs 2、value_coef 1.0、minibatch 512（内存否决）等一批
- `cmax` 单点显著作废（预注册窗口 t=+0.53）——判决按预注册窗口
- 「RL 超过专家」「scratch 首个超专家」：n=15 重标定 / max-of-k 偏差推翻

**工程红线（踩过两次以上的）**

- 增益类超参微调不可测：SD(Δ)≈0.0137，测 0.5 点需 n>40
- 零初始化掐死注意力——同一 bug 已出现三次（v3 末层 / demand_residual / warmstart 零填充）
- **★ 判"训练有没有发生"不能用 `kl > 0`**——浮点舍入使死掉的 run 也报正数（实测 `kl≈1e-5`、`clip_frac=0` 被判成"在动"）。用 `clip_frac > 0` 或 `kl > 1e-4`。这一个判据错误让**四批"训练结果"实际全是 BC 起点**，延误了多轮结论
- **★ 一个版本号只能指一个模型**：`v4` 曾被两个不同模型共用（需求隔离 vs LSTM），导致诊断建立在错误的模型上。见 [`实验产物规范.md`](实验产物规范.md) §3.4
- n=5 显著性必须先怀疑选择偏差；跨节点读数不可混入配对
- 门/判据类代码必须打印输入；新通路实验必须打印梯度范数
- **代码只在本地改**，服务器只跑（服务器上改的代码不会回到 git，却会留在产物里）
- 训练/评测/探针一律在服务器跑；`outputs/` 只增不删

### 方法论纪律（比任何单个实验都重要）

- 预注册窗口 + 预注册判据，**判决只按预注册口径**（cmax 教训）
- 配对比较的两侧必须同机、同配置链、同种子协议
- 训练种子是分辨率瓶颈：加训练种子而不是验证种子
- 诊断场景只能筛「能不能学」，不能定「哪个更好」
