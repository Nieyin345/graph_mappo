## 0. 一句话主张

在真实轨道与气象驱动、每个节点只有 1 Tx + 1 Rx 的天地一体（地面站 / HAP / 卫星）QKD 网络里，密钥生成调度本质上是**带库存与时限的逐时隙端口匹配问题**。
我们用"GNN + 请求–路径注意力 + 链路使用预测辅助头"的强化学习调度器求解它：在 90 个留出任务上全面优于专家启发式和滚动时域 MILP，高负载下把"专家 → 上界"的差距缩小 55–60%；它还能零样本泛化到未见热点、节点失效和不同网络规模，决策时间随规模线性增长。

## 2. 论文脉络（逐节：展示什么、用什么证据）

### §1 引言
- 动机：卫星 / HAP QKD 链路稀缺、时变、受天气影响；端口是硬约束；请求有时限；密钥可以提前囤。
- 难点三个：①组合动作空间（端口匹配）；②延迟回报（囤货收益在 GAE 有效视界约 17 步之外）；③规模与拓扑变化。
- 贡献 C1–C4。

### §2 相关工作（定位新意）
- 卫星 QKD 调度多用 MILP / 启发式：单星对地 MILP（Polnik 2020），单下行多星机会调度（2025-12，逐时隙二分匹配）。它们都不含多层中继、库存与请求时限的联合在线决策，也没有学习。
- QKD 网络 RL：Q-learning 路由（Photonics 2025），GAT+LSTM 端到端密钥供给（JNSM 2025），都是地面网络、无端口匹配。
- SAGIN 的 GNN+DRL：资源分配 / 路由已有（JSAC 2025 等）⟹ 架构本身不是新意。
- 组合动作 RL：结构化 RL / 组合优化层（2025），指针网络 / 构造式解码。
- 辅助任务 RL：UNREAL 等通用辅助任务；本文区别在于"指向请求路径的 QKD 专用标签 + 机制证据"。

### §2' 系统与信道模型
- 草稿 `docs/论文草稿_第2节_系统与信道模型.md`，式 (1)–(19)，参数占位，**等用户改完速率代码再定**。

### §3 问题建模
- 时隙匹配动作、请求与服务、MDP、流体 LP 上界。
- **需要修正**：①奖励是整形奖励（见 §3 参数表），不是"只按服务量"；②节点数 88（30 GS + 30 HAP + 30 SAT 去掉 Stockholm 的 GS 与 HAP）。
- **新增"上界"小节**：精确整数 MILP 在 T=60/120/240 都解不完根节点（1800 s，HiGHS）；精确截止期（bucket=1）只使上界下降 ≤0.21 点；端口松弛等价于桶内分时，可以用整数轮换近似。

### §4 方法
- 4.1 异构图观测；4.2 请求–路径注意力 + 顺序匹配采样器；4.3 预测头。
- 超参表要补上：辅助优化器 lr 3e-4（独立 Adam，同时更新编码器），采样温度 1.2。

### §6 分析
- 6.1 损失解剖：约 12% 不可达；专家"存量耗尽"大；RL 集中激活；剩余最大可控损失 = 端口冲突（4.7 / 5.8 点）与错过预备（3.0 / 4.6 点）。
- 6.2 为什么"更多信息 / 更强结构"单独不起作用：神谕预测、神谕囤货、前瞻（lite 3× +.011，full 3× +.008、2× −.005）。
- 6.3 剩余差距：端口冲突 → 1 号的动机。
- **新增 6.4 负面结果**：deficit 标签（两种学习率都显著变差）；辅助优化器学习率的影响。

## 3. 参数（主模型实际生效值，来自 `load3x_b15_v8bias_fix_s42/resolved_config.yaml`）

### 3.1 场景与环境
| 参数 | 取值 | 备注 |
|---|---|---|
| 节点 | smart 选取 30 GS + 30 HAP + 30 SAT，排除 Stockholm ⟹ **88 节点** | 注册表 0–29 GS、30–59 HAP、60–89 SAT |
| 链路类型 | gs_hap, gs_sat, hap_sat, sat_sat | 训练网络约 1948 条候选链路，平均每时隙约 168 条活跃物理边 |
| 端口 | 每节点 1 Tx + 1 Rx | 动作 = 端口可行匹配 |
| 时隙 / 回合 | 60 s / 240 时隙（4 h），随机起始日 | 训练日 0–295，验证与留出日 330–365 |
| 切换代价 | 新激活链路当时隙速率 × 0.5 | `switch_cost.rate_decay_factor` |
| 速率 | H5 数据集（真实轨道 + 气象） | **待用户替换速率模型** |

### 3.2 请求
| 参数 | 取值 |
|---|---|
| 到达 | Poisson，1× = 0.8 / 时隙；1.5× / 2× / 3× = 1.2 / 1.6 / 2.4 |
| 日内曲线 | 24 个小时权重（0.1–1.3） |
| 量 | 截断指数，均值 1e5 bit，上限 5e5 |
| 时限 | 30 时隙 |
| 热点 | 站对 Zipf(s=1)，pair_seed 0（训练）/ 1、2（留出，未见） |
| 路由 | link_path，最短可用路径（正存量），EDF 服务顺序 |

### 3.3 密钥池
| 链路类型 | 容量 (bit) |
|---|---|
| GS–HAP | 2e7 |
| GS–SAT / HAP–SAT | 8e6 |
| SAT–SAT | 1.2e7 |
| 初始 / 寿命 / 溢出 | 0 / 1e6 时隙（实际不过期）/ 丢弃 |

### 3.4 奖励（整形；论文 §3.3 需改写）
- `mode: shaped`，`reward_scale 0.002`。
- 服务项：`served_weight 50`，参考 1e5。
- 存量项：`storage_reward_weight 0.5`，参考 1e6。
- 失败惩罚：`failed_weight 5`，按到达量归一化。
- 过期惩罚：`expired_key_weight 0.01`。
- 保持激活：`keep_active_weight 0.001`。
- 另有 `success_enabled`、`raw_generation_enabled`。
- 其余项关闭（切换、溢出、冲突、等待、稠密）。
- 评价指标仍是成功率 SR = 已服务量 / 到达量（按量加权）。

### 3.5 模型
| 模块 | 取值 |
|---|---|
| 编码器 | 边条件异构消息传递（graphsage 型）3 层，hidden 128，ReLU，LayerNorm，残差，需求融合到节点，actor/critic 共享 |
| 弧打分 | `attention_only`：请求–路径注意力（arc_query，4 头，≤4 跳）+ 线图注意力；打分 MLP [128, 128] |
| 空闲打分 | MLP [128] |
| 采样 | masked categorical，顺序匹配采样，STOP；温度调度 1.2→1.0 / 1000 次更新（20 次更新内 ≈1.2） |
| critic | 按节点类型均值池化 + MLP [128, 128] |
| 预测头 | K=8，标签 "new"，loss_weight 0.05，pos_weight 8.5，偏置 w=0.2·zscore(tanh(logit)) |
| 预测头优化器 | 独立 Adam，**lr 3e-4**（回落值），同时更新编码器，每次 PPO 更新前 1 epoch，batch 256 |
| 无注意力变体 | 弧打分 MLP [128]（机制实验基准） |

## 6. 论文里必须如实写明的点

1. 注意力臂与无注意力臂的 BC 起点不同（附 update-0 对比）。
2. full_la 与 full 的头随机初始化不同（u0 27.97 vs 26.81），不是逐位配对。
3. 奖励是整形奖励；评价指标是 SR。
4. 辅助优化器 lr 3e-4 是代码回落值（actor_lr 在 optimizer 节，ppo 节读不到）；我们测过 3e-5 更差。
5. 加宽错位的历史与修复（附录 B）。
6. 速率模型替换后需要重跑（内部注意事项，不进论文）。
