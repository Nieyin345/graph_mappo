### 3.2 切口勘察（结构勘察 + **两条被推翻的直觉**）

**「协调方式」这个变量，代码里确实切得开**：

| 项 | 位置 | 含义 |
|---|---|---|
| **协调机制** | `qkd_rl/env/action_resolver.py:130` `_resolve_mutual_choice` | `u->v` 生效 **iff** `u` 的 Tx 指向 `v` **且** `v` 的 Rx 接受 `u`（**互选**） |
| **开关** | `configs/env_full.yaml:21` `action_resolver.mode` | 四值：`mutual_choice`（**现用**）/ `priority_matching` / `greedy_rate_matching` / `max_weight_matching` |
| **实际采样** | `qkd_rl/rl/algos/policy.py:107` `_sample_matching` | **顺序**（不是一次独立 argmax）的在**可行弧 + STOP** 上采样，掩码同时表达 Tx-out≤1 / Rx-in≤1 / 对端不同 |
| **critic 作用域** | `qkd_rl/rl/models/graph_mappo.py:690` `GlobalCritic` | 全局池化（`typed_mean`），`gae.py` 每步**一个标量**，全体 agent 共享同一 advantage |
| **暖启动** | `qkd_rl/rl/algos/mappo_trainer.py:1410` | **已有** `_upgrade_state_dict_for_model`，widened/dropped/missing 全**大声打印** |

#### ★★ 推翻之一：`mutual_choice` **不是**「学出来的协调」

我原以为互选是策略学出来的。**不是**：它**在初始化时就冻结了**。
策略提交 `(tx, rx)`，但**哪个 (tx,rx) 组合会被接受，完全由环境的规则决定**。
actor 只学「报哪个邻居」，**互选协议本身从没被优化过**，永远静止。

⟹ 所以「把协调从策略里摘掉」在 `mutual_choice` 下**没有对应的改动**。

#### ★★ 推翻之二：「每节点独立选」+ `mutual_choice` = **一个无用的策略**

`qkd_rl/baselines/_matching.py:1-12` 的 docstring 是**项目自己早就试过的记录**：

> 「per-node greedy baselines 以前**各节点独立**选自己最好的链路。
> 在 `mutual_choice` 下**几乎从不产生被激活的边**（两端必须互选），
> **所以那些策略实际无用**。……改成全局贪婪匹配，并提交**互选**动作。」

**这是直接的实测证据**：独立选择 + 互选 ⟹ 退化成 `greedy_matching` = **0.1416**
（§1 表里最差的一档）⟹ 那不是「协调变弱」，是**根本不工作**。

⚠ 由此还能推出一步：因为 `stop_logit` 是**可学习标量**而互选是**冻结规则**，
「不协调」真发生时（两个 agent 互抱死锁），**任何学习都解不开**。
这正是 `env.py:169-174` 那条 `RuntimeError` 在保护的东西。

#### ⟹ 正确的对照形态（**必须换 `priority_matching`**）

「去协调」臂必须让**环境替策略裁决**，而不是让互选规则拒绝它：

| 臂 | 改法 | 变量 | 风险 |
|---|---|---|---|
| ~~**A″. 去图**~~ | ~~`model.mode: demand_edge`~~ | — | ⚠⚠ **不是消融**，见下 |
| ~~A. `num_layers: 0`~~ | — | — | ⚠ **两个变量**（Adam 动量会丢），见 §3.3 第 0 条 |
| **B′. 去协调** | `action_resolver.mode: priority_matching` | 策略提方案 vs 环境裁决 | 中（见 §3.3-b） |
| **C. 真·单智能体** | 单个全局 actor（非每节点独立） | **最贴合 H₁ 字面** | 高（需写代码） |

#### ★★★ 推翻之三（2026-09-20，本轮新查）：**`model.mode` 不是「去图」消融**

原文写的「`demand_edge` 在 `num_layers:0` 下与 `mixed` 逐位相同，因为
`fuse_physical_to_node` **只在层内被读**」—— **这句话本身就是自相矛盾的错误**：
正因为只在层内被读，`num_layers:0` 时两份配置**都**不读它 ⟹ 两者当然相同，
但那不是「`mode` 的效应」，是「层数为 0 把 `mode` 架空了」。

**实测（`graph_mappo.py`）**：`model.mode` 全仓库**只有一个真实使用点** ——

```python
# graph_mappo.py:773
self.encoder = GraphEncoder(..., fuse_physical_to_node=(self.mode == "mixed"))
```

而这个 flag 在 `EdgeConditionedGraphLayer.forward` 里只控制**一件事**
（`:254`）：

```python
if self.fuse_physical_to_node and n_phys > 0:
    aggregated = aggregated + self._node_message(self.message_mlp_phys, ...)
```

| | `mode: mixed` | `mode: demand_edge` |
|---|---|---|
| 物理链路边 → 节点消息 | **有** | **无**（不再聚物理边信息到节点） |
| 需求边 → 节点消息 | 有 | 有 |
| 节点→边更新（`phys` / `demand`） | 有 | 有 |
| **张量形状** | — | **完全相同**（`edge_scorer` 仍是 `hidden*3`）⟹ 暖启动**零损失** |
| `SharedNodeActor.self.mode`（`:411`） | 赋值后**从未被读** —— 死代码加解释性注释 | 同 |

⟹ **它是「物理链路边消息的消融」，不是「图结构的消融」。**
图结构（消息传递、边条件更新、边→节点→边）**两种 mode 下都在**。

**另一条实测**：`mode_de_s{42,43,44}` **三条臂早就跑完了**，且原始文件
**在本机镜像 `server_results/outputs/` 里**（`metrics.jsonl` + `resolved_config.yaml`
+ `rollout_debug.jsonl`）。所以 §3.4 里「先跑 A″」是**多余的** —— 直接重标定即可。

**⟹ 要真正做「去图」，只能 `num_layers: 0`**（那条路已升格为 §3.3 第 0 条的问题），
或者走 **C**（真·单智能体）。`mode_de` 顶多算「物理链路通道的消融」。

#### ★ **B′ 的语义必须重新理解：它是「贪心解码器」，不是「环境替策略裁决」**

原文把它写成「让环境替策略裁决」，**读代码后不成立**。`priority_matching`
（`action_resolver.py:154-186`）做的是：

1. 从策略提交的 `(tx, rx)` 里收集候选弧（`:168-175`）
2. 按 `edge_scores` 打分（策略给出的分数！）
3. `_sort_candidates` 排序（`tie_break: rate_then_edge_id`）
4. `_greedy_match` 贪心去冲突（`used_tx` / `used_rx` / `used_pair` 三条约束）

⟹ **它消费策略的分数，所以它读策略的偏好**，只是**解码确定化**了。

⚠ **而且它大概率跑不起来**：`rollout_workers.py:73-77` 在
`priority_matching` 下**仍然传** `expected_matched_edges=list(step.matched_edges)`，
而 `env.py:169` 会校验「resolver 执行的匹配 == 策略采样的匹配」。
策略用**顺序 Gumbel 采样**（`policy.py:107`），resolver 用**确定性贪心**
（`action_resolver.py:319`）—— 两者只在**采样恰好按分数降序取**时才一致，
一般情形**必然不等** ⟹ `RuntimeError`。

⟹ **动 B′ 前必须先回答**：`priority_matching` 下这条校验是否必然失败？
若是，正解是 `env.step(..., expected_matched_edges=None)` 并把 log-prob
口径同步换掉（§3.3-c）—— **那就不是「纯配置」了**。

### 3.3 ⚠ 六条硬约束（**动手前必须逐条过，否则对照不成立**）

#### ★★ 第 0 条（最要命）：`num_layers: 0` **不是**「只改一个变量」—— Adam 动量会丢

结构勘察**推翻了我自己的方案 A**。链条是这样的：

1. `num_layers: 0` ⟹ 删掉 `encoder.layers.{0,1,2}.*` 共 **72 个张量**

2. `_upgrade_optimizer_state_for_model`（`mappo_trainer.py:149-152`）的映射规则是

`clip_eps=0.1 / target_kl=0.02` 一次更新就被突破** ⟹ 口径换了要重新标定这两个值。

`RolloutStep.value` 形状、`compute_gae` 的 per-node TD。
只去中心化 actor 而保留全局 critic ⟹ 切口就只是 (a)(b)(c)，
是**「只改协调方式」的干净对照**。

**e. 环境规则一旦改动，u1 指纹必须变。**

### ★ 4.1 一处**两 regime 矛盾**，必须如实写（不能只写「更差」）

`minibatch 512` 与 `value_coef 1.0` 在**诊断场景**（240 步、固定第 0 天）里
**是仅有的两个越过专家线的变体**（0.8226 / 0.8221，各 +0.0397）。

但搬到**真实配置**后（重标定）：`mini512` 学习上测不出（t=+2.53）且内存 +17.5%；
`value_coef 1.0` 的 SD 恶化 6.7 倍。`epochs 2` 也一样（诊断场景有害、真实配置 t=−1.09 测不出）。

⟹ **诊断场景的排名不迁移**（记录自己就写了「真实预设和诊断预设不是一回事」）。
论文写消融时**必须两个 regime 都列**，否则读者会以为我们没试过。

### ★ 4.2 一条方法错误：**用「绝对水平 vs 外部锚点」当判据是循环论证**

记录里我自己犯过并记下来了 —— 因为它很容易重犯：

> 我曾写「专家锚**独立证实**了配对 Δ」，理由是 `alr1e3 − 专家 = −0.0133`、
> `对照 − 专家 = +0.0133`，两者差 0.0266 ≈ 配对 Δ 0.0242。
>
> **这是循环的**：专家是**本节点**测的，而那个对照是**旧节点**跑的。
> 「对照 − 专家 = +0.0133」里**混着跨节点偏置**。
> 用干净对照重算：`ent01_rerun − 专家 = −0.0087`（**对照自己也在专家之下**），
> 于是 `alr1e3 − 对照 = −0.0133 − (−0.0087) = −0.0046` ⟹ **效应消失**。

**判据**：拿「绝对水平 vs 外部锚点」当证据时，**必须先确认对照组相对该锚点也是干净的**。
否则锚点只是把**同一个未记账变量**再算了一遍，看起来像独立证据。
（好在**专家锚本身节点无关** —— 它是纯启发式、无 matmul ——
所以偏置全在 RL 那一侧，不抵消。）

### 复算脚本必须焊死的三条（每条都对应一次实测事故）

1. **eval 轮号按文件顺序交错读**，不按位置推 `seq*5`
   —— `eval_validation` 行**没有 `update` 键**；续跑把计数器归零但**追加**同一文件
   ⟹ 按位置推会**整体错位**。
2. **未知 df 一律抛错**，不许 `.get(df, 2.0)` 式静默宽松回退
   —— 曾有判读脚本拿 **df=14** 的 2.145 去判 **df=1** 的 t（真值 12.706，偏松 6 倍），
   若 |t| 落在 2.145~12.706 之间就会**宣布假显著**。
3. **逐训练种子配对 + 臂不能跨节点搬**
   —— 不配对时 15 种子 SE≈0.062，配对后 ≈0.012（**差 5 倍**）；
