# 项目结构与文档整理说明（2026-10-09）

## 整理目标与实际范围

本轮仅对文档入口和**可确认不属于当前模型的材料**做保守整理。未执行 Git reset/clean，未修改模型、训练、业务调度或 H5 计算代码，也没有删除数据和 checkpoint。项目本来就有大批在编辑或尚未提交的文件，因此不宜用“Git 显示未跟踪”作为删除依据。

### 结果摘要

- `docs/` 顶层原有 **43 个文档/PPT 文件**；其中 **16 份**历史资料已迁入已存在的 `归档/`，根目录原有资料剩余 27 份（另新增本整理说明）。
- 更新 `docs/00_索引.md`，权威信道规范改为 **v7.5**，不再把 v7.2 写成最新版。
- 重写根目录 `README.md` 为简洁项目导航；**原文件存在乱码，但已原样备份**在 `docs/归档/过程文档/README_整理前乱码备份_20261009.md`。
- 重写部分乱码的 `configs/README.md`，按默认加载链和 v7.5 主场景归类现有配置；原版备份于 `docs/归档/过程文档/configs_README_整理前乱码备份_20261009.md`，**未移动任何 YAML**。
- 保留所有源码、`configs/`、`dataset/`、`weather/`、`outputs/`、`server_results*/`、`reference/` 及 `.tmp/` 原有文件，不做批量移动。

## 项目分层与建议使用方式

| 区域 | 主要职责 | 本次动作 |
|---|---|---|
| `qkd_rl/` | 图环境、密钥库存、请求服务、策略、训练、评测核心 | 不变 |
| `tools/channel_v7/` | 现行信道模型入口 | 不变 |
| `tools/channel_v2/` | v7 仍依赖的部分气象/光学基础代码和历史工具 | **不按旧版本名删除** |
| `tools/dataset_v2/` | 数据集构建、有限密钥/统计聚合 | 不变 |
| `scripts/` | 训练、评估、诊断、绘图、基线与批处理 | 不变 |
| `configs/` | 生产配置、诊断/消融配置，可能有硬编码调用 | 保留，参考 `configs/README.md` |
| `docs/` | 当前规范、验证、实验记录、论文稿及历史归档 | **整理并更新入口** |
| `dataset/`、`weather/` | H5、气象数据源与历史输入 | 保护，不清理 |
| `outputs/`、`server_results*/` | 训练结果、模型权重、评估与复现证据 | 保护，不清理 |
| `.tmp/`、`.pytest-tmp/` | 临时脚本、运行日志及测试临时数据 | **未确认依赖前不得全删** |
| `.archive/`、`_archive/` | 既有不同来源的历史归档 | 暂不合并 |
| `docs/归档/` | 已替代审查、论文过程稿、旧引用汇编 | 统一使用原有目录 |

### 仍显得庞杂但未贸然处理的区域

盘点时 `configs/` 顶层约 **168 项**，`.tmp/` 约 **1780 项**。其中一些脚本、配置或早期复现实验可能通过相对路径硬引用文件，因此本轮只清点、不删不重命名。大容量的 `outputs/`、`dataset/` 与各台服务器镜像同理。今后若要压缩项目体积，应单独做**路径引用审计、试运行和删除清单**，而不是清理器直接删除。

## 怎么判断当前还是历史

1. **信道建模当前唯一入口**：`docs/信道与系统模型规范_定稿草稿_20261005.md`，内容版本 v7.5，日期 2026-10-09。不要只凭文件名日期判断版本。
2. **当前速率简测**：`docs/信道代码审查与场景速率简测_20261009.md`；**动态受控场景**见 `docs/短期信道速率量级验证_20261008.md`。
3. **训练成绩**应回到实验目录检查冻结协议和具体 seeds，而非凭 `docs/当前状态与优化方向.md` 这份 2026-09-24 起始快照得出今天的结论。
4. **论文稿** `docs/论文初稿_中文_v6.md` 留在可见位置以便继续撰写，但并非物理 v7.5 完全同步的声明。
5. 归档文档中的旧路径或旧结论可能按当时目录书写；**不批量重写历史原稿**，引用当代路径请通过 `docs/00_索引.md` 与清单查找。
