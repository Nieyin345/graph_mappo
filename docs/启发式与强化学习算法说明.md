# 启发式算法、对比基线与强化学习算法说明

> 本文覆盖四部分：①我们的启发式算法（BFS 需求扩散 + 分阶段路径调度）；②7 个对比基线的算法原理；
> ③各算法成功率的实测对比；④强化学习算法的结构、设计、训练过程，以及从 BC 预热起点到全局训练的
> 成功率曲线。
>
> 所有数字均来自本仓库的实测运行，标注了协议（固定场景 / 标准验证协议），可直接复现。

## 0. 问题与网络模型（一页）

三层 FSO-QKD 网络，**90 个节点**：30 地面站（GS）、30 高空平台（HAP）、30 卫星（SAT）；
**1978 条候选物理链路**（HAP-GS 63 / SAT-GS 840 / SAT-HAP 900 / SAT-SAT 175），速率来自
`dataset/global/link_data.h5`（全年逐分钟，525600 × 1978，`k_max` 单位 bps）。

每个时隙（1 分钟）智能体要为每个节点决定一条密钥生成链路。物理约束是**双端口**：

- `Tx-out ≤ 1`：一个节点最多向一个邻居发射；
- `Rx-in ≤ 1`：一个节点最多从一个邻居接收；
- **对端不同**：同一对链路在同一时隙不能双向同时开。

被激活的链路按该时隙速率生成密钥存入该链路的密钥池（QKP）；生成的新密钥可以沿多跳中继路径
按**瓶颈跳**部分服务请求。GS 之间按泊松流产生带截止时间的密钥请求。

关键数量级（实测，全规模场景）：每时隙仅约 **9.6% 的 (链路,时隙) 组合速率非零**，平均约 150–270 条
链路可用；网络原始生成能力约 **4.7×10⁶ 密钥/时隙**，而需求约 **6–10×10⁴ 密钥/时隙** ——
**约束不在密钥产量，而在稀疏时变拓扑上的可达性**。

## 1. 我们的启发式算法：BFS 需求扩散 + 分阶段路径调度

启发式由两部分组成：一个**边打分器**（谁值得开）和一个**路径级调度器**（按什么顺序、开整条路）。
它同时是强化学习的**行为克隆专家**（见 §4.6）。

### 1.1 需求扩散重要性（relay importance）

对每个还在等待的请求，用它两端的 GS 当起点，在**当前合法可见的物理边**（并可选地加入"仍持有密钥
库存但当前不可见"的链路）构成的图上做 BFS，得到两个 GS 到各节点的最短跳数。

对边 $i=(u,v)$，令

$$a=\min(d_s(u),d_s(v)),\qquad b=\min(d_d(u),d_d(v)),$$

其中 $d_s,d_d$ 分别是请求源/宿到该边两端点的最短跳数。若 $a,b$ 均连通且 $a+b+1\le K$
（$K$=`max_path_links`，当前 3），则该请求对边 $i$ 贡献

$$\mathrm{relay}_i \;{+}{=}\; B_{pq}\cdot \eta^{\max(0,\,a+b-1)}\cdot \mathrm{scarcity}_i ,$$

其中

- $B_{pq}=\sum_{\text{req}\in(p,q)}\max(0,\text{amount}-\text{served})\cdot \exp(\text{age}/\tau)$，
  $\tau=\text{deadline\_length}\times 0.8$ —— **等得越久、越接近截止时间，压力被指数放大**；
- $\eta=0.25$（`hop_decay_factor`）是每多一跳的衰减；
- $\mathrm{scarcity}_i=(\text{cap}-\text{level})/\text{cap}$ —— 越空的高通量链路越值得用。

最后按本时隙的最大值归一化到 $[0,1]$。这一步把"所有请求对的压力"压成**每条链路一个标量**。

### 1.2 边打分公式（五项）

对每条合法物理边：

$$
s(e)=\underbrace{w_r\,\hat r_e\,(1+w_I \hat I_e)}_{\text{速率}\times\text{重要性}}
\;+\;\underbrace{w_c\,\widehat{\text{comp}}_e}_{\text{补全奖励}}
\;+\;\underbrace{w_k\,\text{keep}_e}_{\text{保持}}
\;-\;\underbrace{w_s\,\text{switch}_e}_{\text{切换惩罚}}
$$

默认权重 $(w_r,w_I,w_c,w_k,w_s)=(1.0,\,10.0,\,1.0,\,0.5,\,0.2)$。各项含义：

| 项 | 含义 |
|---|---|
| $\hat r_e$ | 当前时隙速率 / 当步最大速率 |
| $\hat I_e$ | §1.1 的 relay importance |
| $\widehat{\text{comp}}_e$ | **补全奖励**：若某请求对 $(a,b)$ 由中继 $r$ 两跳可达，且两条边 $a{-}r$、$b{-}r$ 中**恰好一条已有库存**，则缺的那一条获得该请求对的剩余量 |
| $\text{keep}_e$ | 上一时隙已激活，且（重要性>0 或补全>0）→ 1 |
| $\text{switch}_e$ | 上一时隙未激活 → 1（环境对切换链路实际按 0.5 倍速率生成） |

$w_I=10$ 是关键：**重要性把"速率"项放大 11 倍级**，使打分由"是否在需求通路上"主导，而不是由速率主导。

> **只把打分器单独当策略用（边级贪心匹配）只有 0.3215 成功率**（见 §3）。启发式的威力来自
> 打分器 **+ 路径级调度** 的组合。

### 1.3 分阶段路径调度（`phased`）

请求按 **EDF**（最早截止优先，同截止按剩余量大者优先）排序，逐个处理：

1. **阶段 1 —— 现有密钥能否直接服务**：在当前"正库存"网络（含不可见但有库存的边）上查
   `level ≥ amount` 的路径；**能服务就跳过**（不需要任何激活）。
2. **阶段 2/3 —— 拼一条最短可用通路**：依次尝试四种候选集
   `(2跳混合, 2跳纯可见, 3跳混合, 3跳纯可见)`，其中
   - "混合" = 可见边激活 + 不可见边但库存 ≥ 需求，二者拼起来；
   - 每条可见边的可用量按 $\text{level}+\text{rate}\times\text{decay}\times\text{slot}$ 估计，
     `decay = 1.0`（上一时隙已激活）否则 `0.5`（要把切换代价算进去）；
   - 候选路径**按可服务量（瓶颈可用量）优先、余量次之**排序。
   一旦某条路径能立刻用，就**整条路径一次性占下**（双端口，每个节点一收一发）。
3. **阶段 3 —— 原逻辑兜底**：BFS 求最短路径，等长路径中取**V3 边打分之和最大**的那条，整条占下。

### 1.4 贪心填充（Step 2）

分配完请求路径后，剩余空闲端口的边按 V3 打分从高到低贪心占用（优先 `u→v`，冲突则反向），
**为未来时隙积累库存**——这是"预囤中继路径"策略的显式体现。

### 1.5 另一套调度原则（`principles`，备用）

- **第一轮只处理 2 跳**，按"先现有密钥服务 → 再混合 → 再全新"严格分阶段；
- **第二轮**对剩余请求放宽到 3 跳+，但**仍必须当前能立即使用才选**；
- 最后剩余边按分数抢占。

（BC 专家用的是 `phased=True, principles=False`。）

## 2. 对比基线的算法原理

### 2.1 家族 A：全局贪心匹配（共享 `_matching.greedy_matching_actions`）

统一流程：给每条边打分 → 按分降序 → 贪心占用（两端点都空闲且**互为候选**才接受）→ 输出互选动作。
`_matching` 的存在原因：在 `mutual_choice` 解析器下，各节点独立贪心几乎从不产生实际激活的边，
因为必须两端互相选中。

| 策略 | 打分规则 | 设计意图 |
|---|---|---|
| `random` | 均匀随机 | 下界 |
| `greedy_rate` | `rate[0]`（可选：前向窗口均值） | 纯物理层吞吐贪心，完全无视需求 |
| `greedy_qkp` | `level + w_low·(max_level−level) + 0.2·rate` | 库存贪心：填满已有池子有用吗 |
| `greedy_demand` | `demand + 0.2·rate`，`demand` 直连取该 GS 对需求，否则取端点关联 GS 的最大需求 | 需求感知但**连通性盲** |
| `greedy_matching` | `1.0·rate_norm + 0.5·level_norm + 1.0·demand_norm`，再乘 `1+0.5` 若上时隙已激活 | 手工调和 + 避免切换 |
| `greedy_relay` | 按**中继路径**计需求信用，瓶颈速率缩放；**补全半库存路径的边 ×3.0**；deadline 紧迫度 `1+max(0,1−slack/60)`；补全边优先匹配 | 第一个"连通性感知"基线（2 跳 GS→中继→GS） |
| `greedy_relay_diffusion_v3` | §1.2 的五项打分（权重 $(1,10,1,0.5,0.2)$） | 启发式的**打分器**，无路径调度 |
| `greedy_static_relay` | `1.0·rate_norm + 2.0·importance_norm`，其中 importance **在构造时**由全拓扑静态算出 | 消融：动态扩散重要吗 |
| `greedy_relay_v2`（`GreedyRelayScheduler`） | **有状态**：维护 请求对→中继 的持久指派（LRU 淘汰，最多 14 对），每时隙激活"补全跳/较空跳/较快跳" | 消融：粘性指派 vs 每时隙重算 |

### 2.2 家族 B：路径级双端口输出

这些策略直接构造 `(tx, rx)`，把**整条 BFS 路径**一次性占下。

| 策略 | 规则 |
|---|---|
| `path_greedy`（`PathGreedyPolicy`） | 按 EDF 排序请求 → BFS 定最短跳数 → 在最短路径边上做**分层 DP** 最大化 `rate_weight·edge_score` → 整条占下；再用 `dense_fill` 填满剩余端口（优先保持上时隙的边，可选按 relay importance 排序） |
| **`path_score_greedy`（`PathScoreGreedy`，我们的启发式）** | §1.3 + §1.4：V3 打分 + 分阶段路径认领 + 贪心填充 |
| `path_greedy_pair`（`PathGreedyPairPolicy`） | 按 GS 对聚合需求，紧迫度 `exp(age/tau)`；图上含"已有库存的免费边"；BFS 定跳数后只走最短步内的边，最大化 `(0.5 if 免费) + 0.5·rate_norm`；**只激活路径上的缺口边** |

### 2.3 家族 C：MILP 上界

`receding_horizon_milp.RecedingHorizonMILPPolicy`，HiGHS 直接求解，决策变量
`s[e,τ]`（链路库存）、`af/ab[e,τ]`（有向弧，仅在可见时创建）、`f[r,τ]`（服务量）、
`y[r,p,τ]`（路径选择）；约束含逐弧可用性、对端不同（`af+ab ≤ 1`）、双端口匹配、
切换衰减线性化、**精确库存递推**、容量、服务量上界。

> **口径警告（实测）**：仓库里 `compute_milp_upper_bound.py` 实际调用的是
> `relax_multi_path=False` 的**可执行单路径模型**，因此
> ①`--max-paths`/`--max-hops` 是空参数（只在 `relax_multi_path=True` 分支被读）；
> ②成功率分母是 `modeled_amount`（被 `max_requests` 截断后），**不是环境的到达量**；
> ③`switch_decay` 用默认 1.0（关掉了切换代价），而环境是 0.5。
> 所以盘上的 0.111 / 0.173 / 0.153 / 0.854 四个数**互不可比、也不可与下面的成功率并列**。
> 引用前必须统一分母、打开多路径、对齐 `switch_decay`。

## 3. 成功率对比（实测）

### 3.1 固定场景协议

`episode_start_day=0`、`episode_start_mode=fixed`、240 步、请求种子 7–12（12 个），
**确定性策略**（`argmax`/`greedy`，无采样）。这是强化学习训练用的同一场景，方差最小。

| 策略 | 成功率（12 种子均值） | 逐种子 |
|---|---|---|
| `random` | **0.1811** | — |
| `greedy_relay_diffusion_v3`（只有打分器） | **0.3215** | — |
| **BC 预热权重**（克隆自我们的启发式） | **0.7280** | 0.757 / 0.616 / 0.783 / 0.756 |
| **`path_score_greedy_phased`（我们的启发式）** | **0.7765** | 0.803 / 0.658 / 0.850 / 0.796 |
| **强化学习（20 轮后）** | **0.8188** | — |

> 单种子成功率在 **0.616–0.850** 之间波动，所以**4 个种子的均值标准误就有 ±0.04** ——
> 这是为什么所有对比都必须在 ≥12 种子上做（早期用 4 种子做的对比全在噪声里）。

### 3.2 标准验证协议（`global.yaml`：330–365 天 / 5 种子 / 240 步 / 随机日启动）

与基线、MILP 同一协议，可直接并列（`outputs/eval/validation_protocol/summary.json`，
我们的启发式由 `PathScoreGreedy(phased=True)` + `ServeProbe` 单独补测）。

| 策略 | 成功率 mean ± std | 逐种子 |
|---|---|---|
| **`path_score_greedy`（我们的启发式）** | **0.8104 ± 0.0575** | 0.771 / 0.752 / 0.866 / 0.878 / 0.785 |
| **BC 预热权重**（克隆自上面的启发式） | 0.7581 ± 0.0714 | — |
| `greedy_relay` | 0.4351 ± 0.0605 | — |
| `greedy_rate` | 0.4337 ± 0.0595 | — |
| `greedy_relay_diffusion_v3`（**只有打分器**） | 0.2943 ± 0.0625 | — |
| `greedy_demand` | 0.1408 ± 0.0797 | — |
| `random` | 0.1259 ± 0.0272 | — |
| `greedy_matching` | 0.0377 ± 0.0549 | — |
| `greedy_qkp` | 0.0071 ± 0.0158 | — |

这张表里有四个值得注意的结论：

1. **我们的启发式（0.810）是最强的非学习方法**，比第二名 `greedy_relay`（0.435）高 **1.86 倍**。
2. **打分器本身很弱**：`greedy_relay_diffusion_v3` 只有 0.294。启发式的威力来自
   **打分器 + 路径级调度**的组合，缺了路径调度就退化到普通贪心的水平。
3. **`greedy_matching`（0.038）比 `random`（0.126）还差**，`greedy_qkp`（0.007）几乎为零 ——
   前者把库存权重混进打分，后者一味填满已有池子，都说明"不按需求通路选边"的策略在这个问题上是负分。
4. **BC 克隆丢了 5.2 个点**（0.8104 → 0.7581）。克隆损失（按决策平均 NLL）在 113–200 之间就平台了
   —— 这是"模仿不充分"，也意味着**改进 BC 可以直接抬高强化学习的起点**，是后续一个明确的收益点。

## 4. 强化学习算法

### 4.1 总体结构

**共享编码器的 Actor-Critic**（多智能体 PPO 在单图场景下的等价形式：所有节点共享策略参数，
Critic 是全局价值函数）。一次前向的流程：

```
观测图 ──► 特征拼接 ──► 图编码器 GNN ──► 节点/边嵌入
                                          ├─► Actor: 逐边打分 ──► 顺序采样全局匹配
                                          └─► Critic: 分类型池化 ──► 全局价值 V(s)
```

### 4.2 输入特征（进入 GNN 之前的三个特征族）

| 族 | 维度 | 内容 |
|---|---|---|
| **节点** | 17 | 类型 one-hot(3)、QKP 库存/容量/利用率(3)、流入/流出需求(2)、队列压力(1)、近 15/60/240 时隙需求(3)、是否有可用邻边(1)、日内与年内 sin/cos(4) |
| **物理边** | 28 | 链路类型 one-hot(4)、当前可用性(1)、当前速率(1)、未来 6 步速率(6)、未来 6 步可用性(6)、速率增量/均值/最大值(3)、上时隙是否激活(1)、relay importance(1)、两端点到最近请求源/宿的跳数(4)、链路剩余容量比(1) |
| **需求边** | 16 | 待服务量、待服务请求数、最小/平均剩余截止、平均等待时长、优先级加权和(6) + **按等待时长分 10 桶的剩余量**(10) |

物理边与需求边各自补零到同一维度 44，由 GNN 用**各自独立的投影**处理。

速率特征用 `log_p99` 归一化（参考值来自 `dataset/global/rate_stats.json`，由
`scripts/estimate_rate_stats.py` 生成）；需求金额用 `log1p(x)/log1p(1e6)`，计数用 `log1p(x)/log1p(100)`。

### 4.3 图编码器

边条件 GraphSAGE，**3 层、隐层 128**：

- 每层：按类型独立的消息 MLP $\varphi^{p},\varphi^{d}$ 作用于 $[h_{src}; e]$，
  按目的地**除以各自入边数**聚合再相加；节点更新 MLP + LayerNorm + 残差；
- 另有**节点→边更新**（边嵌入吸收两端最新节点上下文，残差 + LayerNorm），
  使"需求压力"沿 需求边→节点→物理边 逐层落到边嵌入上；
- 物理边与需求边**从投影到消息传递全程不共享变换**（语义不同：链路能力 vs 请求压力）。

### 4.4 Actor：逐边打分 + 顺序采样全局匹配

1. **打分**：对每条合法有向弧 $(u,v)$，
   $s_{(u,v)}=\mathrm{MLP}^{edge}([\,h_u;h_v;e_{(u,v)}\,])$。有向弧分别打分，所以 $u{\to}v$ 与 $v{\to}u$ 排名不同。
2. **顺序采样**：每一步在"两端点仍空闲、且该对未匹配过"的弧集合 + 一个**可学习的 STOP 选项**上做
   softmax 采样一条；选到 STOP 即结束。这使策略能表达"本时隙什么都不激活"，而不是被迫填满端口。
3. **联合对数概率按决策数取平均**（per-decision mean），与熵的归一化一致 ——
   这是 PPO 的 `clip_eps`/`target_kl` 能有字面含义的前提（见 §4.7）。
4. 确定性评估时取 argmax，得到零冲突的调度。

**为什么用全局匹配而不是"每节点独立提议 + 解析器消解"**：早期版本两者不一致，PPO 优化的提议分布
与环境真正执行的匹配不同，成功率长期停在约 30%；改成"采样的匹配就是执行的匹配"后问题消失
（`QKDEnv.step` 里有一条硬断言：解析器执行的匹配必须等于策略采样的那个）。

### 4.5 Critic

`typed_mean` 池化：节点嵌入均值、物理边嵌入均值、需求边嵌入均值，拼上三个图规模计数
$\log(1+|V|),\log(1+|E_p|/2),\log(1+|E_d|/2)$ → MLP `[128,128]` → 1。
分类型池化避免两类边互相稀释，计数弥补均值池化丢失的规模信息。每个时隙只有**一个**全局价值，
所有节点共享同一优势。

### 4.6 奖励设计（当前 `env_full.yaml`）

$$
r_t=\underbrace{\frac{50\,S_t-5\,F_t-0.01\,E_t}{10^5}}_{\text{服务}-\text{失败}-\text{过期}}
+\underbrace{0.5\cdot\frac{\sum_{e}(\text{added}_e-\text{from\_new}_e)\cdot\text{pathness}_e}{10^6}}_{\text{通路存储}}
+\underbrace{0.001\,K_t}_{\text{保持激活}}
$$

最后整体乘 `reward_scale = 0.002`。各项含义与设计理由：

| 项 | 设计理由 |
|---|---|
| $S_t$（服务量，**全额计分**） | 归因（attribution）**已关闭**。开启时只有"本时隙新生成且当步被消费"的密钥算分，实测服务 43,506 密钥/时隙里只有 7,920（**18.2%**）拿到奖励 —— 也就是"之前囤中继路径"的全部回报对奖励不可见。关掉后奖励与成功率单调一致 |
| $F_t$（失败量，权重 5.0） | 原为 0.01（**每密钥仅 1e-7，等于免费**）。现在一个失败密钥值 0.1 个服务密钥：`served − 0.1·failed` 仍是服务量的单调函数（因为到达量外生），但让"让请求等死"有了真实代价 |
| $E_t$（过期密钥） | 权重 0.01 |
| `storage` | 新密钥存在**某待服务请求当前可用通路**上才给分；权重 0.5/1e6。它奖励"预囤"，与启发式的策略同向 |
| `keep_active` | 保持激活计数 ×0.001（切换在环境里实际按 0.5 倍速率生成，但奖励里看不到这个物理代价） |
| `reward_scale = 0.002` | 全局缩放，**让 critic 能拟合**（见 §4.7） |

**为什么需要 `reward_scale`**：PPO 的 critic 要预测折扣回报，而 Adam 每个优化步只能把参数移动约一个
学习率。未缩放时回报约 **68**，critic 要从 0 爬到 68 结构上做不到。实测病征：

```
value V(s)   std = 0.007      return R  std = 49.2
advantage |A| = 68.8          (≈ 回报本身)
corr(V,R) = 0.20              V_std/R_std = 0.0001
```

即 **critic 退化成常数 → GAE 失去 baseline → 优势等于原始回报 → actor 的梯度基本是噪声**。
缩放后（回报 ~0.7）：`|A|/R` 1.16 → **0.050**，`V/R` 0.030 → **0.920**，`corr(V,R)` −0.13 → **+0.18**。

### 4.7 训练过程

**每个 update 的流程**：

1. **Rollout**：8 局并行（随机日/固定日由 profile 决定），每局 `rollout_steps` 步。
   单进程 lockstep、每 4 张图组成一次块对角前向（实测 4 图 14.2 ms/图 vs 8 图 51.2 ms/图，
   所以**分批比一次堆宽更快**）。
2. **GAE**：$\delta_t=r_t+\gamma(1-d_t)V(s_{t+1})-V(s_t)$，
   $A_t=\delta_t+\gamma\lambda(1-d_t)A_{t+1}$；$\gamma=0.99,\ \lambda=0.95$。
   截断（非终止）的局用 bootstrap 接续。
3. **PPO**：1 个 epoch，minibatch 256，clip 0.1，`normalize_advantages`，
   **策略与价值分开裁剪**（`max_grad_norm=0.5`），目标 KL 0.02 触发早停，
   entropy_coef 0.001，value_coef 0.5，actor_lr 3e-4 / critic_lr 1e-3（Adam）。
4. **记录**：`metrics.jsonl`（含 `V_std`/`R_std`/`corr(V,R)`/`actor_grad`/`critic_grad` 等诊断）、
   `rollout_debug.jsonl`（奖励逐项分解），定期 checkpoint。

**BC 预热（行为克隆）是必需的 —— 实测证据**：

- 专家 = §1.3 的 `PathScoreGreedy(phased=True)`；克隆损失 = 专家匹配在策略顺序采样器下的
  **按决策平均 NLL**（`-mean_log_prob`），轨迹来自 `outputs/trajs_pg_phased`（295 天）；
- 实测：64×2 的小模型**从零训练 3 轮 `kl = 0.0000`、`ratio = 1.0000`，actor 完全不学**；
  而 BC 预热的手臂正常爬升。
- 预热把起点从"随机 ≈0.18"抬到"≈0.73（固定场景）/ ≈0.86（训练窗口逐局均值）"，
  **跳过前期大量试错**。

### 4.8 一路上修掉的数值/工程缺陷（都已验证）

| 缺陷 | 病征（实测） | 修复 |
|---|---|---|
| 奖励量级未归一化 → critic 报废 | `V_std/R_std = 1e-4`，`|A| = R`，`corr = −0.13` | `reward.reward_scale` |
| 归因抹掉 82% 服务奖励 | 43,506 服务中仅 7,920 计分 | `attribution_enabled: false` |
| 失败惩罚约等于零 | −0.0013 vs +4.06（0.03%） | `failed_weight` 0.01 → 5.0 |
| `keep_active_reward` 被分支丢弃 | 配置打开却从没进过 `total` | 补上 + 3 个回归测试 |
| PPO 口径不一致 | `clip_eps`/`target_kl` 挂在 40 项求和的 joint log-prob 上，熵却除以决策数 → 实测 `kl` 恒 > `target_kl`，**每个 update 早停于第 2 个 minibatch（只走 1 个优化步）** | 全部改为**按决策归一化** |
| 全局梯度裁剪饿死 actor | actor 只占梯度能量 **4.01%**（actor 头 0.045 vs critic 头 1.071） | **策略/价值分开裁剪**（策略组范数实测 0.26–0.31，不再被裁） |
| rollout 与更新的温度不一致 | worker 进程收不到 trainer 退火中的温度 → old/new log-prob 系统性偏离 | 把温度随权重下发 |
| 两处 O(决策×弧) 的 Python 扫描 | PPO 复评里 7.03 ms/图（占 minibatch 46%）；采样器 3.60 ms/步 | 整数编码掩码，**逐位一致**，3.2× / 2.2× |
| 每轮 rollout 7.7 万次 GPU 同步 | `.detach().cpu()` 逐边读分数 | 默认解析器不需要分数时完全跳过 |
| 观测缓冲 9× 冗余 | 每条 obs 0.519 MB（含无人读的 `EnvState`） | 创建 `RolloutStep` 时剥离 → 0.057 MB |
| 环境构造的 2 秒死预计算 | `GraphBuilder.__init__` 枚举 435 GS 对 × 1978 边 | 删除（只被测试调用） |

**一个反直觉的实测结论**：策略的**熵在上升**（3.17 → 3.87）而**确定性成功率同时上升**
（0.728 → 0.819）—— 说明 BC 先验**过度自信**了，不要用熵正则去压它。

## 5. 成功率曲线：从 BC 起点到全局训练

### 5.1 起点：BC 预热把成功率抬到哪里

| 参照点 | 协议 | 成功率 |
|---|---|---|
| 我们的启发式（专家） | 标准验证协议，确定性，5 种子 | **0.8104** |
| **BC 预热权重** | 标准验证协议，确定性，5 种子 | **0.7581** |
| **BC 预热权重** | 固定场景，确定性，12 种子 | **0.7280** |
| **BC 预热权重** | 训练窗口，随机日逐局（采样策略） | **0.858**（update 1 的 8 局均值） |
| 随机初始化（对照） | 固定场景 | ≈ 0.18 |

三条曲线用不同协议，不可互相比较；它们各自的作用是：
**0.8104** 是启发式给强化学习设的天花板参照；**0.728/0.758** 是"预热后的确定性起点"；
**0.858** 是"预热后在训练窗口上、用采样策略跑出来的逐局均值"，也就是强化学习曲线的时间零点。

### 5.2 固定场景验证曲线（12 种子确定性评估，每 5 轮一次）

| update | 5 | 10 | 15 | 20 |
|---|---|---|---|---|
| **确定性成功率** | 0.7560 | 0.7858 | **0.8188** | 0.8175 |

对照：BC 起点 0.728 / 最好的启发式 0.7765 / 随机 0.181。
**20 轮内净升 +0.091，并在第 15 轮超过启发式 +0.042。** 作为对照，修复前的配置在 20 轮里
一直卡在 0.718 不涨。

> ⚠️ **这条提升没有迁移到全窗口训练** —— 见 §5.3/§5.4。这个场景只有一天、一条请求流，
> 涨得快但也容易只学到"针对这一天的策略"。它是**验证"算法与奖励能不能把成功率推上去"
> 的受控实验台，不是泛化能力的证据。**

### 5.3 全窗口训练曲线（随机日、变请求；30 轮）

训练窗口 = `global.yaml` 的 0–295 天随机日，每轮 8 局 × 1440 步；
验证 = 标准验证协议（330–365 天、5 种子、240 步、确定性），每 5 轮一次。

| update | 训练均值（8 局采样） | 训练 reward | entropy | **验证（确定性）** |
|---|---|---|---|---|
| 1（= BC 起点） | 0.8576 | 92.15 | 3.163 | — |
| 5 | 0.8654 | 95.87 | 3.380 | 0.7064 |
| 10 | 0.8502 | 90.47 | 3.743 | 0.7149 |
| 15 | 0.8669 | 98.40 | 3.953 | **0.7589** |
| 20 | 0.8622 | 93.85 | 4.042 | 0.7105 |
| 25 | 0.8538 | 93.45 | 4.160 | 0.7289 |
| 30 | 0.8416 | 90.85 | 4.322 | **0.6589** |

**诚实解读：这条曲线没有上升，反而可能在下滑。**

- **验证成功率无趋势**：6 次评估 = 0.706 / 0.715 / 0.759 / 0.711 / 0.729 / 0.659，
  均值 0.713 ± 0.033。协议本身只有 5 个种子（单种子 std ≈ 0.07，SEM ≈ 0.03），
  这个区间和"纯噪声围绕 0.713 波动"完全一致。
- **对照**：BC 起点在同一协议上是 **0.7581**，启发式是 **0.8104**。
  也就是说强化学习**没有超过它的起点**，而且水平在起点下方约 4.5 个点
  （0.713 vs 0.758，约 1.1 个标准差，方向上不利但尚未构成显著差异）。
- **训练侧指标全平**：8 局采样均值 0.858 → 0.842，reward 92 → 91，30 轮无趋势。
- **唯一系统性变化是熵**：3.16 → 4.32，单调上升 +1.16。
  即策略在持续变得更随机，但没有变得更好。
- **critic 全程健康**：`corr(V,R) = 0.89`、`V/R = 0.85–0.91`（会话开始时是 0.18 / 0.0001）。
  所以这不是 critic 的问题。

### 5.4 固定场景的提升没有迁移 —— 这是当前的核心问题

同一套算法在**固定场景**上 20 轮涨了 9 个点（§5.2：0.728 → 0.819，超过启发式），
在全窗口上 30 轮**原地不动**。两者唯一的实质差别是：

| | 固定场景 | 全窗口 |
|---|---|---|
| 场景数 | **1 个**（day 0） | 295 个随机日 + 昼夜周期 |
| 每轮梯度看到的数据 | 同 8 条请求流 | 8 个不同日子 |
| 12 种子的评估噪声 | SEM ≈ 0.006 | SEM ≈ 0.031（协议只有 5 种子） |

最可能的解释是**梯度信噪比**：固定场景每轮看到同一条流，梯度方向一致，所以能稳定爬升；
多场景下每轮看到不同的日子，方向被采样噪声主导，策略只是随机游走
（熵单调上升正是随机游走的伴生现象）。**100 个梯度步（30 轮）对多场景显然不够。**

**已经成为确凿事实的三条（都不是方向性证据）**：

1. 确定性解码与采样解码的差距只有 **2–4 个点**（不是我在过程中一度以为的 14 点 ——
   那个数字来自把训练窗口的采样均值和验证窗口的确定性结果相比，属于窗口混淆）；
2. 用**全局最大权匹配**替代顺序贪心解码**更差**（0.448 vs 0.758）：
   边分数不是匹配权重的量纲，最大权匹配会为了总分去激活大量中等分的边，把端口填满；
3. **优势的跨批标准化不是问题**：跨局方差只占 5.4%（`corr(advantage, 本局平均回报) = +0.082`）。

**行为层面的实测差距**（验证窗，每条 51 万次激活）：三个策略激活的边数几乎相同（59–60），
但 RL 挑的链路**中位速率低 30%**（2160 vs 启发式 3109），且 **3.8% 的激活落在 <10 bps 的
垃圾链路上**（可用池里这类只占 0.9%）—— 启发式只浪费 2.1%。不过按测算这**不构成服务瓶颈**：
服务量只差 1.6%，而生成量是需求的约 200 倍。可操作的小修是把 `min_link_rate` 从 1.0 bps
提到 100 bps 量级，直接删掉那 4–6% 的无效动作。

### 5.5 还能往哪里查

按"证据强度 × 成本"排序：

1. **更多训练**（最高置信度）：60–300 轮。快场景（40 s/轮、12 种子评估、SEM 0.006）
   比全窗口便宜 6 倍，适合先在那里验证"欠训练"这个假设。
2. **提高 actor 学习率**：`kl` 长期只有 0.001–0.004，单步位移偏小。
3. **收紧动作掩码**：`min_link_rate` 1.0 → 100 bps（有实测依据，但顶多值几个百分点）。
4. **熵正则**：熵单调上升 +1.16 且无收益，`entropy_coef` 0.001 可考虑降到 0 做消融。
5. **改进 BC 起点**：克隆丢了 5.2 个点（0.8104 → 0.7581），直接把起点抬上去比让 RL 爬上去更确定。
