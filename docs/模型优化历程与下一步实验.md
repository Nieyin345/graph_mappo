## 任务与最初模型

每个时隙选择要激活的**有向物理链路集合**，受每节点 Tx-out≤1、Rx-in≤1 等端口约束；环境负责密钥生成、库存、路由和请求服务。目标是提高按密钥量计算的服务成功率，而不只是让单条边得高分。早期 GraphMAPPO 使用节点、物理边、逻辑需求边构成的图，GNN 编码后由共享 edge scorer 给候选有向边打分，顺序匹配采样器连同 STOP 选择可行集合，critic 估计全局价值。BC 模仿启发式实际执行的匹配，再用 PPO 更新。

最初的简单启发式（随机、库存优先、需求优先、速率优先、中继优先）在 2026-09-21 的**新环境**、留出窗 330–365 天、请求种子 100–114、240 步下，成功率分别约 0.130、0.121、0.297、0.490、0.492。PG-Phased 专家为 **0.767**。此前旧环境有不可达节点；删节点使专家配对成功率从 0.698 升到 0.767，因此旧环境的训练臂不能和新环境数字直接排名。见[实验日志 §1–2](实验日志.md)。

## 演进时间线

| 阶段 | 当时要解决的问题 | 改动与证据 | 结论 |
| --- | --- | --- | --- |
| 专家与 BC 热启动 | 初版 GNN 从零训练慢，动作空间有端口组合约束 | PG-Phased 按库存路径、混合库存路径、全新路径服务请求，空余端口再做预备；BC 学的是环境**实际执行的有向匹配**。诊断场景专家约 0.7886、BC 起点约 0.7680 | BC 降低冷启动难度；启发式评分器单独用不等于完整专家 |
| 训练底层诊断 | “训练后不提升” | 修复 checkpoint 恢复时旧 Adam 参数组覆盖 actor 学习率；区分采样训练值和确定性留出验证；逐请求种子配对；固定线程数。奖励审计发现服务主项占绝对值约 102%，库存/保持激活项各约 0.1%，长期备货信用弱 | 先修训练/评估口径，才能谈模型增益；1440 步真实训练与 240 步筛选不能混称 |
| 第一轮需求感知尝试 | 让边感知请求和路径 | 早期 `demand_edge` 模式、`on_pending_path` 特征、`bottleneck` 特征、DemandResidual 附加头依次尝试。旧日志在各自协议下记录：`demand_edge` 约 −0.052，`on_pending_path` +0.008，`bottleneck` +0.0154；DemandResidual 五种子平均 +0.0146，但同向仅 3/5、t=1.76 | 没有足够证据证明“给旧 scorer 再加需求输入”能稳定增益；这些是**实验臂名称**，不要与后来的 model_zoo v2/v3 混淆 |
| v2 结构与筛选 | 需要统一、快速地比较模型 | v2 保留 GNN 后的基础边打分通路，使用同一 BC→PPO→留出验证流程；把快速筛选的单局改为 240 步。其 50 次更新与旧 v3 20 次更新的结果曾被并排展示，但预算不同，不能作架构结论 | 建立同数据、同训练预算、同验证窗口的配对实验要求 |
| v3 注意力主导 | 旧 scorer 主导时难判断注意力是否有贡献，也缺少边的连接关系 | 去掉 actor 的旧基础 scorer 残差，候选弧分数由 pair-path attention 主导；每个请求独立选 4-hop 候选路径，物理边 token 显式带两个端点的身份向量；query 含候选弧自身，路径边再做共享端点的 self-attention | 结构符合“请求对自己的候选边做注意力，输出边分数”的设计；不能只凭单次高分宣称成功 |
| v3 评分 bug 修复 | 初跑 v3 比 v2 差、PPO 几乎不动 | 路径外弧备用分数被 `norm.clamp_min(1e-6)` 放大一百万倍，部分分数约 −1648；旧 BC 打分头 99.45% ReLU 输出为零。只改前向，同旧权重留出均值 0.7211→0.7528；旧 v3 PPO KL 约 1e-9 | 旧 v3 低表现首先是实现错误和坏 BC 权重，不能据此否定注意力 |
| 修复后的 v2/v3 同预算短跑 | 验证注意力主导结构是否值得继续 | 同 8 天专家轨迹 BC、训练种子 42/43/44、240 步、10 次 PPO、验证窗 330–365 天/请求种子 100–114。第 10 次：v2 **0.7281**、v3 **0.7376**；v3 第 5 次 **0.7426**，末次回落 | v3 有小幅短训收益，但密钥效率和训练速度仍需改善；还不是注意力独立效应的证明 |
| v3 权重审计 | 注意力是否正常工作 | checkpoint 无 NaN/Inf，打分层 ReLU 零值约 57%，PPO 后注意力权重相对变化中位数约 0.08%–0.10%。80 个留出状态中，四头最大注意力权重中位数 0.969/0.999/0.502/0.320 | 两头较尖锐、两头保留分散信息；需要独立测试“过尖”是否妨碍成功率 |
| v3 需求隔离 | 不同请求经 GNN 共享节点互相混合 | 增加 `fuse_demand_to_node: false`。旧节点记录原 v3 **0.7376**、隔离版 **0.7565**，另一窗口 **0.8244→0.8545**；原始产物已丢失。冻结重训反向：A **0.7628→0.7503**，B **0.8559→0.8385** | 旧正向读数不能作为论文结论；冻结协议下隔离显著退化，机制原因待消融 |

### 不能合并成一条曲线的数字

早期诊断场景固定第 0 天、240 步、请求种子 7–18；真实配置曾用 1440 步并在 0–295 天随机起始；冻结短训用 240 步、留出窗 330–365 天、请求种子 100–114。环境节点数也曾变化。`0.8359`（旧诊断场景）、`0.767`（新环境专家）和旧隔离版 `0.7565` 不能据绝对值判优。当前可直接比较的核心组是冻结评测中同训练与评测协议的 v2、v3、隔离版。

## 旧节点实验协议（仅用于解释历史）

- 代码：旧服务器 `/opt/qkd/pairhist-v3-attention-only-20260923`。原 v3 保持默认需求传播；隔离版通过 `qkd_rl/model_zoo/v3/config_demand_isolated.yaml` 显式关闭。
- BC：相同的 `outputs/traj_v3fixed_60d/day_0000`–`day_0007` 8 个专家日，batch 64。PPO：种子 42/43/44，10 次更新，每次 8 个 240 步 rollout，actor LR 1e-5。
- 主验证：330–365 天，请求种子 100–114，15 集×240 步。第二窗口：300–329 天，请求种子 200–214，同样 15 集×240 步。报告逐训练种子和均值，同时看生成/服务秘钥比（越低越省）。
- 原始日志与 checkpoint：随 clnode263 释放丢失，不可复核。

## 现行冻结协议与反转排查

以 [`冻结评测报告`](../server_results_node342/frozen_20260924/冻结评测报告.md) 和 `frozen_eval/` 的 20 份 JSON 为准。旧 BC 只用了名称含 `60d` 的轨迹目录里前 8 个文件，每文件按收集脚本默认值为 **1440 步**，不能写成训练了 60 天；新 live BC 为 8 集 × **240 步**。旧数据显式固定 day_0000–0007，新 live BC 种子为 0–7，却由 `random_day` 抽起点，数据分布也不同。新 PPO 将自回归匹配的 log-prob 从逐决策均值改为联合求和，BC 仍用均值。以上均是已核实的协议差异，尚不能断言哪一项造成了反转。

当前 `fuse_demand_to_node: false` 只关闭需求边传入节点的消息。节点输入仍包含 demand_in/out、queue_pressure、recent_demand 聚合量，需求边编码还会读取共享端点节点，因而它**不是请求之间完全隔离**；同时它会移除需求边向物理图传递的即时请求上下文。冻结退化可能来自信息损失、BC 覆盖不足或 PPO 目标改变，须在同一冻结代码与评测协议下做单变量消融。

## 下一步注意力实验

先在现行冻结协议下以普通 v3 为基线：分别固定 BC 数据只切换需求消息开关、固定模型与 BC 数据只切换 PPO 概率目标，并增加 BC 后、PPO 前的同窗评测，找出退化从哪个阶段开始。BC 数据应缓存并供两臂逐步复用，评测继续使用 `scripts/eval/frozen_eval.py`。在此之前暂停把隔离版作为温度实验的基线；温度和注意力移除消融应在稳定基线上分别进行。
