## 3. 问题建模

### 3.1 时隙决策

时间离散为 1 分钟时隙 t。每个时隙，网络控制器为每个节点选择**至多一条**要激活的量子链路：
每个节点只有 1 个发送端口（Tx）和 1 个接收端口（Rx），因此被激活的有向链路集合 \(A_t\) 必须是
**端口可行匹配**——任一节点至多作为一条激活链路的发端、至多作为一条的收端。
激活的链路 \(e\) 在本时隙生成 \(R_e(t)\) 比特密钥（§2.2 的动态信道速率；上一时隙未激活、本时隙新激活的链路
因重新对准只按半速率生成），存入该链路的密钥池（容量按链路类型给定），密钥寿命足够长、不过期。

### 3.2 请求与服务

量子通信请求在地面站对之间以泊松过程到达（日均 0.8 个/时隙，叠加 24 小时业务曲线，热点站对服从 Zipf 分布），
每个请求需要 \(K_r\) 比特密钥（截断指数分布，均值 0.1 Mbit），时限 30 个时隙。
服务沿**给定路由**进行：每个时隙请求沿一条正存量最短路消耗沿途各链路密钥池中的密钥，可部分服务、跨时隙累计。
路由由环境固定（对所有策略相同），调度策略只决定「给哪些链路生成密钥」——即把调度与路由解耦，
这使得端口成为唯一的稀缺控制资源，也使 MILP 上界与所有策略在同一服务语义下可比。

**评价指标**：成功率 SR = 已服务密钥量 / 到达请求的密钥总量（按量加权）。

### 3.3 马尔可夫决策过程

状态 = 各链路当前速率与可见性、各密钥池存量、待服务请求集合（及其剩余量、剩余时限、路径）、端口占用；
动作 = 端口可行匹配 \(A_t\)；奖励 = 本时隙服务的密钥量（归一化），使回报与 SR 单调一致。
每集 240 个时隙（4 小时），起始时刻在 30 天仿真窗口内随机选日。

### 3.4 上界

我们用**流体线性规划（fluid LP）**给出每个请求种子的可证上界：
把整数匹配松弛为端口的分数约束，并**事先告知**整集的请求到达与链路速率（即全知、可分割），
求最大可服务量。任何在线策略都不可能超过它，因此它是「天花板」而非可达基线。
（早期版本中的「MILP 上界」经审计不是有效上界，已弃用。）
可执行的对照另取**滚动时域 MILP**（RH-MILP：窗口 30 时隙、每 10 时隙重规划、每次求解限时 30 s）。

## 4. 方法：链路使用预测辅助的图强化学习调度

### 4.1 异构图观测

每个时隙把网络编码为一张异构图：节点为地面站 / 高空平台 / 卫星（类型 one-hot + 本地特征）；
**物理边**为当前候选量子链路（链路类型、当前速率、密钥池存量、上一时隙是否激活等）；
**需求边**连接有待服务请求的地面站对（剩余量、剩余时限、路径长度等）。
物理边与需求边共同参与消息传递，使请求压力沿物理链路扩散到路径上的中继节点。
编码器为 3 层**边条件异构消息传递**（隐藏维 128）：物理边与需求边各用独立的消息 MLP
（输入为源节点嵌入与边嵌入的拼接），按类型分别做邻居均值聚合、再相加，经节点更新 MLP + LayerNorm；
随后每条边再用本类型的边更新 MLP 吸收两端点的新嵌入（残差 + LayerNorm），
因此跨层之后边嵌入携带路径上下文——需求信息经「需求边 → 端点 → 物理边」逐层落到链路上。
actor 与 critic 共享编码器。

### 4.2 策略与联合匹配采样

候选有向弧 \(a=(u\to v)\) 的分数 \(s_a=\mathrm{MLP}([h_u, h_v, e_{uv}])\)，另有每节点「空闲」分数与全局 STOP 分数。
动作由**顺序匹配采样器**生成：每一步在仍可行的弧与 STOP 之间做 softmax 采样，选中后删去与之争端口的弧，
直至 STOP 或无可行弧。该过程的联合对数概率可精确计算，因此 PPO 的重要性比率对应的正是环境实际执行的匹配。
训练采用集中式 critic 的 PPO（MAPPO 形式，γ=0.99，λ=0.95），以作者的路径贪心启发式做行为克隆暖启动，
随后 20 次 PPO 更新。

### 4.3 链路使用预测辅助头（本文核心）

**动机**。「提前为将来的请求在关键链路上攒密钥」是高负载下的主要机会，但其回报是**延迟的**：
GAE 的有效视界约为 \(1/(1-\gamma\lambda)\approx 17\) 个时隙，而一次预备决策的收益常常在更远处才兑现，
且被同时刻其他动作的回报稀释。单靠策略梯度，这类决策几乎拿不到信号。

**做法**。为每条物理边加一个辅助头 \(g(e)=\mathrm{MLP}([h_u,h_v,e_{uv}])\)，预测

\[
y_t(e)=\mathbb{1}\big[\,e \text{ 在未来 } K=8 \text{ 个时隙内出现在某个请求的服务路径上}\,\big].
\]

标签在回合结束时由记录下来的每时隙路径掩码回读得到，**不依赖策略行为**（是请求自己的路径集合），
因此不能被「囤密钥」刷高。辅助头以带正例权重的 BCE 训练，每次 PPO 更新前单独训练一轮
（其梯度同时塑形共享编码器）；决策时把它的输出作为**行为偏置**加到弧分数上：

\[
s_a \leftarrow s_a + w\cdot \mathrm{z\text{-}score}\big(\tanh g(e_a)\big),\qquad w=0.2,
\]

偏置在图内做 z-score，使其尺度与辅助头的绝对输出解耦；偏置对策略梯度截断（detach），
保证 PPO 在同一个策略下采样与重评估。

**与注意力的关系**。我们同样实现了**请求–路径注意力**（每条候选弧以自身为 query，
attend 到当前请求路径上的链路 token 与需求 token）。§5.4 的 2×2 消融显示：注意力在有无预测头时都不带来增益；
增益完全来自预测头。本文主模型因此采用 **GNN + 预测辅助头（无注意力）**，注意力作为诚实报告的消融项。

## 5. 实验

### 5.1 设置

- **场景**：29 个地面站 + 高空平台 + 30 颗卫星，四类链路（GS–HAP、GS–SAT、HAP–SAT、SAT–SAT），
  速率由真实轨道与气象（云层、大气衰减）驱动的 H5 数据集给出；每集 240 个时隙。
- **负载**：到达率相对基准的倍率 {1, 1.5, 2, 3}×（0.8 → 1.2 / 1.6 / 2.4 个/时隙），每个负载点**单独训练**。
- **评测协议**：
  - dev 集：15 个请求种子（100–114），只用于模型选择；
  - **留出集（报告口径）**：30 个新请求种子（1000–1029）× 3 组热点站对（pair_seed 0/1/2；
    训练只见过 pair_seed 0，1/2 的热点站对**完全未见**），共 90 个评测任务。
  - 每个 RL 方法 3 个训练种子（42–44），报告均值；显著性按请求种子配对 t 检验（n=30）。
- **所有策略**在同一批任务上配对评测，任务指纹逐一核对一致。

### 5.2 对比方法

| 方法 | 说明 |
|---|---|
| Path-Greedy（专家） | 作者设计的路径感知贪心启发式：按请求路径打分，贪心构造端口可行匹配；也是 BC 暖启动的示教者 |
| RH-MILP | 滚动时域 MILP（W=30，每 10 时隙重规划，限时 30 s） |
| Graph-MAPPO（v2） | 边条件图卷积编码器 + PPO（本项目最初的图 RL 版本） |
| GNN-PPO | 本文编码器 + PPO，无注意力、无预测头 |
| GNN + 注意力 | GNN-PPO + 请求–路径注意力 |
| GNN + 注意力 + 预测头 | 上者 + §4.3 辅助头 |
| **本文：GNN + 预测头** | GNN-PPO + §4.3 辅助头（无注意力） |
| GAT-PPO | 邻居聚合改为 GATv2 式多头注意力（每目标节点 softmax），无预测头——文献中常见的图注意力 RL 基线 |

### 5.6 期刊加强实验（batch-12，⏳ 运行中）

三组实验都只改一个变量，并逐一核对：各臂第 0 次更新的 rollout 奖励与对照**逐位相同**
（GAT 的注意力向量零初始化 ⟹ 初始即均值聚合；换标签不影响首轮采样）。均为 2×/3× 负载 × 3 种子，留出集评测。

**(a) 预测标签是否必须是 QKD 专用的？** 同一预测头、损失与偏置管线，只换标签：
- persist：链路在 (t, t+K] 每一步都保持可用（可见且速率 ≥ 1）。与需求无关的通用信道/可用性预测，
  正例率 0.62（pos_weight 按同一规则 (1−p)/p = 0.61）；
- shuffle：本文「new」标签在同一时隙内随机置换——正例数、类别平衡、额外梯度量完全相同，但不含「哪条边」的信息。
若本文增益来自「多一个监督信号的正则作用」，shuffle 应接近本文；若来自「预测信道」本身，persist 应接近本文。

**(b) 图注意力编码器能否替代预测头？** GAT-PPO（无预测头）对照 GNN-PPO；GAT + 预测头对照本文。

**(c) 环境感知的价值。** 用 `--ideal-channel` 重建全年链路数据（晴空、无日照背景，仅几何传播损耗 +
固定晴空大气），映射到同一链路集（仅速率不同）。不经大气的 SAT–SAT / SAT–HAP 链路与真实数据逐位相同；
经大气的链路差异显著：

| 链路类型 | 条数 | 真实天气平均速率 | 理想信道平均速率 | 比值 | 可用时隙占比（真实 → 理想） |
|---|---|---|---|---|---|
| SAT–GS | 840 | 3.84 | 10.34 | 2.69× | 1.57% → 3.18% |
| HAP–GS | 63 | 1549.9 | 2234.7 | 1.44× | 37.8% → 38.6% |
| SAT–SAT / SAT–HAP | 1075 | — | — | 1.000 | 逐位相同 |

即真实天气使星地链路的可用时间减半、平均速率降为理想值的约 37%。天气盲策略（BC 与 PPO 均在理想数据上训练）
在真实天气留出集上评测，对照天气感知的本文策略；同时报告专家与上界在两种信道下的数值，量化天气本身的影响。

| 负载 | 专家（理想/真实） | 上界（理想/真实） | 天气盲策略 | 本文（天气感知） |
|---|---|---|---|---|
| 2× | ⏳ / .7008 | ⏳ / .8348 | ⏳ | .7688 |
| 3× | ⏳ / .6290 | ⏳ / .8155 | ⏳ | .7397 |

## 6. 分析：增益从哪里来，剩下的差距在哪里

### 6.1 损失解剖

我们把每个到达请求的未服务量逐时隙归因到互斥的类别（dev 前 5 个种子，训练种子 42）：

- **真正不可达**：即使把回合开始以来出现过的所有链路都算上，请求两端仍不连通——约 13.6–13.9%，
  对所有策略完全相同，是场景（卫星可见性与天气）决定的硬损失；
- 在**可达**需求上（2×）：上界服务 94.6%，本文 86.5%，专家 82.8%。

**表 5** 本文方法的可控损失构成（占到达量的百分点）：

| 类别 | 2× | 3× |
|---|---|---|
| 错过预备（需要时链路不可见、事前未攒） | 3.1 | 4.9 |
| 端口冲突（链路可见但端口被别的弧占用） | 2.8 | 6.7 |
| 存量耗尽（与端口无关） | 2.3 | 3.4 |
| 存量被别的请求抢用 | 0.9 | 0.9 |
| 端口空闲却没激活 | 0.5 | 0.4 |

预测头的作用在这张表上一目了然：「**端口空闲却没激活**」这一类从无预测头时的 2.1–2.7 个百分点降到 0.5；
注意力在任何一类上都没有可测差别。

### 6.2 为什么「更多信息 / 更强结构」不起作用

我们对剩下的两大类损失分别做了便宜的「神谕」诊断：

1. **预测精度不是瓶颈**：辅助头的 AUC 为 0.70–0.74；把它换成**真值标签**（神谕预测）几乎没有额外收益（≈0）。
2. **前瞻信息不是瓶颈**：把接触计划（未来 120 个时隙的可见性分桶、当前接触剩余时长、间隙）作为特征输入，
   2×/3× 均无效应（|Δ| ≤ .003，t ≈ 0）；
3. **预备本身的上限很小**：在行为偏置里直接注入「哪些边需要预备」的神谕信息，最多只多 +.003 ~ +.004
   （约 13% 的请求需要预备，每时隙仅 2.2–2.6 条正例边）。

结合表 3：在 GAE 约 17 个时隙的有效视界下，额外的信息（前瞻特征）或额外的容量（注意力）都没有转化为更好的策略；
**唯一起作用的是给每个决策一个致密、与策略无关的监督信号**（§4.3）。
这也是本文把方法贡献落在「预测辅助头」而非更复杂编码器上的原因。

### 6.3 剩余差距：端口冲突

端口冲突是剩余可控损失中最大的一类（3× 6.7 个百分点）。我们尝试了**端口冲突注意力**：
每条候选弧 attend 到与它争同一端口的候选弧（同发端 / 同收端 / 反向弧），以零初始化残差加在弧分数上，
使打分能看到竞争者。该模块零初始化、从同一 BC 起点训练，与主模型严格单变量对照。

结果（dev 集，3 训练种子）：叠加在本文方法上 2× −.001、3× +.002；叠加在无预测头的 GNN 上 +.005 / +.003，
均不显著。失败解剖显示它**确实作用在端口冲突这一类上**——3× 下端口冲突损失平均从 5.92 降到 5.44 个百分点
（无预测头时 7.47 → 6.91，6 个配对中 5 个下降），但幅度小于训练种子间的方差。
留出集（90 个任务）进一步确认：叠加在本文方法上 2× −.0003、3× +.0002，6 组 |t| ≤ 1.6。
因此在当前训练预算下，把注意力放在端口竞争上能对准损失类别，但收益可以忽略；
端口冲突仍是后续工作最值得攻克的方向（例如以匹配层面的结构化解码替代逐弧打分）。

## 7. 结论

本文在真实轨道与气象驱动的天地一体化 QKD 网络中研究端口受限的密钥生成调度。
我们提出链路使用预测辅助的图强化学习调度：在 GNN 策略上增加一个预测「哪些链路即将被请求路径使用」的辅助头，
用它的致密监督信号塑形表示并作为行为偏置。在 90 个留出评测任务上，该方法在全部负载下都显著优于专家启发式（+3.5 ~ +11.1 个百分点），
高负载下把与流体 LP 上界的差距缩小 51–59%，并且在未见过的热点站对上同样有效；
可执行的滚动时域 MILP 反而不及专家。消融与损失解剖表明，增益来自图上下文与致密监督的结合，
而非注意力或额外信息（去掉消息传递下降 13 个百分点；请求–路径与端口冲突两种注意力设计均无增益），
剩余差距主要来自端口冲突与场景本身的不可达。
