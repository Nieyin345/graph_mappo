## 3. 问题建模

### 3.1 时隙决策

时间离散为 1 分钟时隙 t。每个时隙，网络控制器为每个节点选择**至多一条**要激活的量子链路：
每个节点只有 1 个发送端口（Tx）和 1 个接收端口（Rx），因此被激活的有向链路集合 \(A_t\) 必须是
**端口可行匹配**——任一节点至多作为一条激活链路的发端、至多作为一条的收端。
激活的链路 \(e\) 在本时隙生成 \(R_e(t)\) 比特密钥（§2.2 的动态信道速率；上一时隙未激活、本时隙新激活的链路
因重新对准只按半速率生成），存入该链路的密钥池（容量按链路类型给定），密钥寿命足够长、不过期。

### 3.2 请求与服务

量子通信请求在地面站对之间以泊松过程到达（日均 0.8 个/时隙，叠加 24 小时业务曲线，热点站对服从 Zipf 分布），
每个请求需要 \(K_r\) 比特密钥（截断指数分布，均值 0.1 Mbit），时限 30 个时隙。
服务沿**给定路由**进行：每个时隙请求沿一条正存量最短路消耗沿途各链路密钥池中的密钥，可部分服务、跨时隙累计。
路由由环境固定（对所有策略相同），调度策略只决定「给哪些链路生成密钥」——即把调度与路由解耦，
这使得端口成为唯一的稀缺控制资源，也使 MILP 上界与所有策略在同一服务语义下可比。

**评价指标**：成功率 SR = 已服务密钥量 / 到达请求的密钥总量（按量加权）。

### 3.3 马尔可夫决策过程

状态 = 各链路当前速率与可见性、各密钥池存量、待服务请求集合（及其剩余量、剩余时限、路径）、端口占用；
动作 = 端口可行匹配 \(A_t\)；奖励 = 本时隙服务的密钥量（归一化），使回报与 SR 单调一致。
每集 240 个时隙（4 小时），起始时刻在 30 天仿真窗口内随机选日。

### 3.4 上界

我们用**流体线性规划（fluid LP）**给出每个请求种子的可证上界：
把整数匹配松弛为端口的分数约束，并**事先告知**整集的请求到达与链路速率（即全知、可分割），
求最大可服务量。任何在线策略都不可能超过它，因此它是「天花板」而非可达基线。
（早期版本中的「MILP 上界」经审计不是有效上界，已弃用。）
可执行的对照另取**滚动时域 MILP**（RH-MILP：窗口 30 时隙、每 10 时隙重规划、每次求解限时 30 s）。

## 4. 方法：链路使用预测辅助的图注意力强化学习调度

### 4.1 异构图观测

每个时隙把网络编码为一张异构图：节点为地面站 / 高空平台 / 卫星（类型 one-hot + 本地特征）；
**物理边**为当前候选量子链路（链路类型、当前速率、密钥池存量、上一时隙是否激活等）；
**需求边**连接有待服务请求的地面站对（剩余量、剩余时限、路径长度等）。
物理边与需求边共同参与消息传递，使请求压力沿物理链路扩散到路径上的中继节点。
编码器为 3 层**边条件异构消息传递**（隐藏维 128）：物理边与需求边各用独立的消息 MLP
（输入为源节点嵌入与边嵌入的拼接），按类型分别做邻居均值聚合、再相加，经节点更新 MLP + LayerNorm；
随后每条边再用本类型的边更新 MLP 吸收两端点的新嵌入（残差 + LayerNorm），
因此跨层之后边嵌入携带路径上下文——需求信息经「需求边 → 端点 → 物理边」逐层落到链路上。
actor 与 critic 共享编码器。

### 4.2 策略与联合匹配采样

**请求–路径注意力打分**。把每条物理边表示为链路 token \(x_e=[h_u,h_v,e_{uv}]\)。先做一层**线图注意力**：
每个链路 token 只 attend 到与它共享端点的链路 token（4 头，残差），使链路之间的连接关系显式化。
随后对每个「候选弧 \(a\) × 待服务站对 \(p\)」组合（\(a\) 位于 \(p\) 的某条 ≤4 跳候选路径上），以
\(q_{a,p}=W_q[x_a^{\mathrm{arc}}, x_a, d_p]\)（弧自身嵌入、所在链路 token、站对的需求嵌入）为 query，
在 \(p\) 的路径链路 token 上做 4 头缩放点积注意力得到上下文 \(c_{a,p}\)，再由
\(s_{a,p}=\mathrm{MLP}([x_a^{\mathrm{arc}}, c_{a,p}, d_p])\) 打分；弧分数 \(s_a\) 是各站对分数按请求权重的加权平均
（不在任何路径上的弧使用加权汇总的站对上下文）。另有每节点「空闲」分数与全局 STOP 分数。
直观上，一条弧是否值得激活取决于它服务于哪些请求的哪条路径、以及路径上其他链路的状态——注意力让打分直接读取这些上下文，
并能在同一站对的多条候选弧之间排序。
（轻量变体「本文-无注意力」用 \(s_a=\mathrm{MLP}([h_u,h_v,e_{uv}])\) 代替注意力，§5 的机制实验在它上面进行。）
动作由**顺序匹配采样器**生成：每一步在仍可行的弧与 STOP 之间做 softmax 采样，选中后删去与之争端口的弧，
直至 STOP 或无可行弧。该过程的联合对数概率可精确计算，因此 PPO 的重要性比率对应的正是环境实际执行的匹配。
训练采用集中式 critic 的 PPO（MAPPO 形式，γ=0.99，λ=0.95），以作者的路径贪心启发式做行为克隆暖启动，
随后 20 次 PPO 更新。

### 4.3 链路使用预测辅助头（本文核心）

**动机**。「提前为将来的请求在关键链路上攒密钥」是高负载下的主要机会，但其回报是**延迟的**：
GAE 的有效视界约为 \(1/(1-\gamma\lambda)\approx 17\) 个时隙，而一次预备决策的收益常常在更远处才兑现，
且被同时刻其他动作的回报稀释。单靠策略梯度，这类决策几乎拿不到信号。

**做法**。为每条物理边加一个辅助头 \(g(e)=\mathrm{MLP}([h_u,h_v,e_{uv}])\)，预测

\[
y_t(e)=\mathbb{1}\big[\,e \text{ 在未来 } K=8 \text{ 个时隙内出现在某个请求的服务路径上}\,\big].
\]

标签在回合结束时由记录下来的每时隙路径掩码回读得到，**不依赖策略行为**（是请求自己的路径集合），
因此不能被「囤密钥」刷高。辅助头以带正例权重的 BCE 训练，每次 PPO 更新前单独训练一轮
（其梯度同时塑形共享编码器）；决策时把它的输出作为**行为偏置**加到弧分数上：

\[
s_a \leftarrow s_a + w\cdot \mathrm{z\text{-}score}\big(\tanh g(e_a)\big),\qquad w=0.2,
\]

偏置在图内做 z-score，使其尺度与辅助头的绝对输出解耦；偏置对策略梯度截断（detach），
保证 PPO 在同一个策略下采样与重评估。

**预测头为什么有效：表征，而不只是偏置**。§5.4 的逐项分解显示，增益的大部分来自辅助头的**监督信号对共享编码器的塑形**
（只训练头、偏置为 0 时已拿到全部增益的 80% 以上，有无注意力两种结构上一致），行为偏置贡献其余部分；而单独把 path-recency 特征加进输入则没有任何效果。
也就是说，起作用的是「让表示去预测哪些链路即将被请求路径使用」这一**任务**，而不是额外的输入信息。
标签的内容同样关键：在无注意力变体上，把标签在时隙内随机置换、或换成与需求无关的链路持续可用标签，都会让性能大幅低于不带预测头的基线；在完整模型上，置换标签损失预测头增益的约 2/3（§5.6(a)）。

**注意力与预测头的互补**。§5.4 的 2×2 析因显示：单独加入请求–路径注意力**没有**增益（2× −.009、3× −.005），
而在带预测头时注意力在全部四个负载上都显著有益（+.006 ~ +.020）。一个自然的解释是：注意力要从路径上的链路 token 中挑出关键链路，
而预测头的监督信号恰好让链路嵌入携带「是否即将被请求路径使用」的信息——没有这一信号，注意力没有值得关注的内容。
本文完整模型因此为 **GNN + 请求–路径注意力 + 链路使用预测头**。

## 5. 实验

### 5.1 设置

- **场景**：30 个地面站 + 30 个高空平台 + 30 颗卫星，四类链路（GS–HAP、GS–SAT、HAP–SAT、SAT–SAT），
  速率由真实轨道与气象（云层、大气衰减）驱动的 H5 数据集给出；每集 240 个时隙（1 分钟 / 时隙）。
- **负载**：到达率相对基准的倍率 {1, 1.5, 2, 3}×（0.8 → 1.2 / 1.6 / 2.4 个/时隙），每个负载点**单独训练**。
- **评测协议**：
  - dev 集：15 个请求种子（100–114），只用于模型选择；
  - **留出集（报告口径）**：30 个新请求种子（1000–1029）× 3 组热点站对（pair_seed 0/1/2；
    训练只见过 pair_seed 0，1/2 的热点站对**完全未见**），共 90 个评测任务；留出日期（330–365）与训练日期（0–295）不重叠。
  - 每个 RL 方法 3 个训练种子（42–44），报告均值；显著性按请求种子配对 t 检验（每负载 90 个配对，或每组 30 个）。
- **所有策略**在同一批任务上配对评测，任务指纹逐一核对一致。
- **单变量**：同一打分结构的 RL 臂从同一个行为克隆 checkpoint 暖启动（有 / 无注意力两种结构各一个 BC，示教者、数据量与训练预算相同）；新增输入特征时对应权重按特征布局补零，
  使初始策略与对照前向等价（附录 B 记录了一次已纠正的实现错误，本文所有数字均来自纠正后的重跑）。

### 5.2 对比方法

| 方法 | 说明 |
|---|---|
| Path-Greedy（专家） | 作者设计的路径感知贪心启发式：按请求路径打分，贪心构造端口可行匹配；也是 BC 暖启动的示教者 |
| RH-MILP | 滚动时域 MILP（W=30，每 10 时隙重规划，限时 30 s） |
| Graph-MAPPO（v2） | 边条件图卷积编码器 + PPO（本项目最初的图 RL 版本） |
| GNN-PPO | 本文编码器 + PPO，无注意力、无预测头 |
| + recency | GNN-PPO + path-recency 输入特征（预测头使用的特征），无预测头 |
| + 预测头（仅表征） | 上者 + §4.3 辅助头，偏置 w=0（只通过监督信号塑形编码器） |
| 本文-无注意力：GNN + 预测头 | 上者 + 行为偏置 w=0.2（机制实验的基准模型） |
| GNN + 注意力 | GNN-PPO 的弧打分换成 §4.2 的请求–路径注意力，无预测头（注意力 BC 起点） |
| **本文：GNN + 注意力 + 预测头** | 完整模型（注意力 BC 起点） |
| GAT-PPO / GAT + 预测头 | 邻居聚合改为 GATv2 式多头注意力（每目标节点 softmax）——文献中常见的图注意力 RL 基线 |
| 标签对照 | 本文结构，仅把标签换成与需求无关的「链路在未来 K 步持续可用」（persist），或把本文标签步内随机置换（shuffle） |
| 天气盲 | 本文方法，但 BC 与 PPO 全部在理想信道（无天气）数据上训练，在真实天气上评测 |
| 流体 LP 上界 | §3.4，全知可分割松弛，不可达 |

## 6. 分析：增益从哪里来，剩下的差距在哪里

### 6.1 损失解剖

我们把每个到达请求的未服务量逐时隙归因到互斥的类别（dev 种子 100–109；RL 为 3 个训练种子的均值；「本文」为无注意力变体，与 GNN-PPO 同一 BC）：

**表 7** 损失构成（占到达量的百分点；专家 / GNN-PPO / 本文）。

| 类别 | 2× | 3× |
|---|---|---|
| 真正不可达（回合内所有出现过的链路都算上仍不连通） | 11.7（三者相同） | 11.9（三者相同） |
| 错过预备（需要时链路不可见、事前未攒） | 2.6 / 2.9 / 3.0 | 4.7 / 4.5 / 4.6 |

- 约 12% 的到达量由卫星可见性与天气决定、任何策略都救不了；
- 专家几乎不漏选端口，但把端口分散激活在很多链路上，每条链路攒不够量（「存量耗尽」5.5 / 8.2）；
  图 RL 学会了集中激活，这一类降到 2–3；
- 预测头相对 GNN-PPO 主要减少「端口空闲却没激活」（2.7 → 1.3、3.6 → 1.4）与高负载下的端口冲突（7.1 → 5.8）、存量被抢（2.0 → 1.2）；
- 剩余可控损失中最大的是端口冲突（4.7 / 5.8）与错过预备（3.0 / 4.6）。

### 6.2 为什么「更多信息 / 更强结构」单独不起作用

我们在本文-无注意力变体上做了三组便宜的诊断（dev 15 种子 × 3 训练种子，逐种子配对；正常模式逐种子复现 validation 结果，差为 0）：

1. **决策时的预测内容不起作用**：评测时把预测头输出换成**真值标签**（神谕预测），2× −.001（t −0.5）、3× +.002（t 0.5）；
   换成图内**随机打乱**的输出，+.001 / +.004（t ≤ 1.0）。预测头 AUC 为 0.70–0.74，但即便完美也不涨。
2. **精确知道该囤哪些边也不起作用**：在偏置里注入由真实到达序列 + 接触计划算出的「该提前囤货的边」（神谕囤货），
   2× +.001（t 0.3）、3× −.003（t −0.9）。
3. **前瞻信息**：把接触计划（未来 120 个时隙的可见性分桶、当前接触剩余时长、间隙）作为特征输入：单独加入（无预测头）2× −.001、3× −.003，不显著；叠加在本文-无注意力上 2× −.001（t −0.5）、3× **+.011（t 4.3）**。前瞻信息只在高负载、且有预测头时有一定作用（需各自的 BC 起点，结构同注意力的交互），幅度小于预测头本身。

结合表 3：recency 特征本身无效、辅助头的监督信号带来绝大部分增益，而偏置虽然在训练中有显著贡献（+.009 / +.008），
决策时替换它的内容却毫无影响——**偏置的作用体现在训练过程（它改变了策略探索与学到的表示），而非决策时提供的信息**。
在 GAE 约 17 个时隙的有效视界下，额外的信息（接触计划）或额外的容量（注意力）**单独**都没有转化为更好的策略；
只有在预测头提供了指向请求路径的监督信号之后，它们才带来小幅但显著的增益（注意力 +.006 ~ +.020；3× 前瞻 +.011）。
**起作用的是给每个决策一个致密、与策略无关、指向请求路径的监督信号——它是其他结构发挥作用的前提**。
这也是本文把方法贡献落在「预测辅助头」而非更复杂编码器上的原因。

### 6.3 剩余差距：端口冲突

端口冲突是剩余可控损失中最大的一类。我们尝试了**端口冲突注意力**：
每条候选弧 attend 到与它争同一端口的候选弧（同发端 / 同收端 / 反向弧），以零初始化残差加在弧分数上，
使打分能看到竞争者。叠加在本文-无注意力上：2× +.001（t 1.8）、3× −.003（t −2.6）；单独加在 GNN-PPO 上 −.001（n.s.）。逐弧打分层面的竞争信息不足以消解冲突。
端口冲突仍是后续工作最值得攻克的方向（例如以匹配层面的结构化解码替代逐弧打分）。

## 7. 结论

本文在真实轨道与气象驱动的天地一体化 QKD 网络中研究端口受限的密钥生成调度。
我们提出链路使用预测辅助的图注意力强化学习调度：GNN 编码器 + 请求–路径注意力打分，再加一个预测「哪些链路即将被请求路径使用」的辅助头，
用它的监督信号塑形表示并作为行为偏置。在 90 个留出评测任务上，该方法在全部 12 组条件下都显著优于专家启发式，
提升随负载单调增大（1× +3.4，3× +10.8 个百分点），高负载下把与流体 LP 上界的差距缩小一半以上，并且在未见过的热点站对上同样有效；
可执行的滚动时域 MILP 反而不及专家，本文在每个种子上都优于它。
2×2 析因表明注意力只有在预测头存在时才有益；逐项分解表明预测头的增益主要来自辅助监督对表示的塑形（80% 以上），而非额外输入特征；
标签内容是增益的主体——在无注意力变体上，随机置换或换成通用的链路可用性预测会造成负迁移、跌到专家以下（即使不经偏置影响决策）；在完整模型上置换标签损失约 2/3 的增益；
收益与编码器选型（均值聚合 / GAT）正交；策略对信道模型失配稳健（理想信道训练、真实天气评测仅损失 ≤0.4 个百分点）。
剩余差距主要来自端口冲突与场景本身的不可达。

## 附录 B：warm start 的特征加宽与一次已纠正的实现错误

所有 RL 臂都从同一个行为克隆（BC）checkpoint 起步（`screen_bc_noatt`，不含 path-recency 特征）。当某个臂新增一个输入特征时，
我们把第一层对应的权重矩阵补一列零，使新模型在初始时刻与 BC 策略**前向等价**，从而保证各臂之间只差被研究的那一个变量。

边特征向量按 `[物理边特征 | 需求边特征]` 拼接（物理边在需求块填零，反之亦然）。path-recency 是一个**物理边**特征，
新增后位于物理块末尾，即行的中间位置。初版实现把零列追加在**整行末尾**，使 16 个需求边特征的权重整体错位一列，
新特征则接收了原需求块第 1 列的已训练权重。受影响的是所有"从无-recency BC 起步且开启 recency"的臂（本文方法及其各消融），
而不含 recency 的基线（v2、v3、无预测、无图、GAT）不受影响。

我们通过一项单变量检查发现了该问题：仅新增 recency 的臂在第 0 次更新时的 rollout 奖励本应与不含 recency 的对照**逐位相同**，实测却不同。
修复后，零列按 checkpoint 中记录的物理/需求块宽度插入到物理块末尾（优化器的一、二阶矩同样处理），
该检查恢复逐位相同（2× 负载 s42/s43：27.571306 / 28.370768）；单元测试覆盖任意 recency 取值下的前向等价，
且把插入改回追加时测试失败。

**本文报告的所有 recency 臂结果均来自修复后的重跑。** 需要说明的是，错位版本在留出集上的成绩并不更差、反而略高：
本文方法修复前后分别为 1× .8003 / .7800、1.5× .7831 / .7702、2× .7688 / .7640、3× .7397 / .7288
（修复后 − 修复前：−.020、−.013、−.005、−.011，1×/1.5×/3× 配对显著）。错位初始化相当于把 BC 学到的需求块输入权重打乱后重新学习，
这提示 BC 暖启动在需求特征上可能存在过拟合、适度扰动反而有利于后续 RL——这是一个值得单独研究的现象，
但它不是本文方法的组成部分，我们不将其计入结果。所有消融（表 3、5 与 §5.6）在修复后才是严格单变量的；
修复前后「预测头为主要增益来源」的结论一致，但修复前的「标签随机置换 ≈ 本文」这一现象在修复后消失
（修复后置换标签远低于本文，表 5），说明它是错位初始化的产物。
