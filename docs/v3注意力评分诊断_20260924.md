# v3 路径外边评分与 BC 退化诊断（2026-09-24）

## 结论

`PairPathAttentionScorer.forward()` 在候选边不属于任何正权重请求路径时，
先计算了备用分数，随后仍对它执行 `result / norm.clamp_min(1e-6)`。
此时 `norm=0`，备用分数被放大一百万倍。旧 checkpoint 的路径外边因此出现约
`-1648` 的分数，策略基本不选这些边。这直接压低未来备货和服务成功率。

旧 BC 训练也使用了这一计算。BC checkpoint 的打分头边分数第 10、50、90
百分位几乎相同（约 `-0.0017`）；第一层 ReLU 输出的元素有 99.45% 为零。
修正代码后，只用一天旧专家轨迹重新 BC，损失约 4.15，零激活比例约 53%，
边分数第 10、90 百分位约为 `-0.67`、`2.52`。原 60 天 BC 日志的累计平均
损失为 1365；两次训练长度不同，这个数值只作为异常量级证据。

| --- | ---: | ---: | ---: |
| 42 | 0.7177 | 0.7576 | 0.7531 |
| 43 | 0.7301 | 0.7509 | 0.7694 |
| 44 | 0.7154 | 0.7499 | 0.7897 |

修正找回约 3.2 个百分点，但旧权重仍比 v2 低约 1.8 个百分点。
v3 只训练 20 次更新，v2 训练到 50 次；不能据此断言架构上限。
修正后 v3 的生成秘钥/服务秘钥比约 129–130，原 v3 约 104–105，
v2 约 97–119；成功率提升伴随更多秘钥消耗。

## 排除与后续

- 旧 v3 PPO 的平均 KL 约 `1e-9`，clip fraction 为 0；从 BC 到第 20 次更新，
  注意力打分头参数的相对 L2 变化约 0.046%。PPO 几乎没有重塑打分头。
- 保持 BC 权重不变、仅清空 Adam 状态做一次 PPO 更新，rollout 完全相同，
  KL 和梯度几乎不变。继承优化器状态不是这次退化的主因。
- 当前留存 BC checkpoint 用修正评分重评，留出成功率为 0.7490；旧权重经过
  20 次 PPO 后的三个种子均值为 0.7528，提升很小。

  330–365 天验证环境后重新合并训练配置，把实际窗口覆盖回 0–295 天。
  当时 checkpoint 后来也被同名文件覆盖。修正窗口后的当前 BC checkpoint
  在旧评分代码下为 0.6881。

## 权重与需求传播复查（2026-09-24）

只读审计脚本 `.tmp/audit_v3_current_20260924.py` 在服务器输出到
`outputs/audit_v3_current_20260924.log`。BC 与三个 PPO 最终 checkpoint
均无 NaN/Inf。BC→PPO10 的注意力参数相对 L2 变化中位数约
0.00084–0.00095；不是完全冻结，但 10 次短训对它的重塑有限。
单个留出状态中弧分数 p10/p50/p90：BC 为 0.49/2.19/5.99，PPO s42
为 0.55/2.21/6.02；评分没有塌成常数。打分头 ReLU 零值占比约 57%，
不像旧错误训练的 99.45%。STOP logit 约 -0.0376，无异常量级。

该状态中一个请求的 6 条路径边被 8 个候选弧查询。4 个注意力头的
平均最大权重分别约 1.000、0.9998、0.611、0.891；前两个头在 8 个
查询中始终选同一条边，归一化熵近于 0，logit 绝对最大值约 40。
这说明该样本中两头显著饱和，且 PPO10 后几乎未改变；仅一个状态不能
证明所有请求都如此，需在留出轨迹上统计覆盖率和头多样性。

当前 `EdgeConditionedGraphLayer` 的需求边→节点聚合，以及随后
节点→需求边/物理边更新，确实提供跨请求混合通路。在第 16 步找到
共享端点的两个请求；把其中一个请求边的全部特征加 1，另一个请求的
最终嵌入相对变化 0.000116，物理边 0.000168，节点 0.00104。
因此共享端点时存在影响，但单样本幅度小；不能仅凭传播通路或此扰动
断言它降低成功率。需要保持其余配置一致，训练“物理图 GNN + 独立需求
编码器”对照，比较相同窗口/种子下的成功率与请求间扰动敏感度。

追加 80 个留出状态、13,366 个有多条可注意路径边的候选查询后，4 个头的
最大注意力权重中位数分别为 0.969、0.999、0.502、0.320；归一化熵
中位数分别为 0.061、0.003、0.514、0.745。前两头普遍非常尖锐，
后两头保留分散信息。尖锐不等于坏；仍需通过独立消融判断这些头是否
有助于最终成功率。

需求隔离对照增加 `model.encoder.fuse_demand_to_node: false`，保留物理图
消息传递和需求边从端点读取物理上下文。共享端点的最小回归测试先因
缺少配置入口失败，加入开关后通过。基线默认值仍为 `true`。
