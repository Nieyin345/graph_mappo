## 4. 进行中：共同起点消融（`/tmp/launch_dgc.sh`，日志 `/tmp/launch_dgc.log`，10-03 05:24Z 起）

**设计**：权重无法跨架构共享，所以"共同起点" = 共同示范数据 + 共同 BC 过程。
- 阶段 0：三个架构各自从 n45 基础 BC 出发，在同一份 `agg3`（1152 回合）上以 `n45_dagger_it3_sw4` 的同一配方

  与 dgsw4 的唯一差别：暖启动点是基础 BC 而非 it2 链（三臂一致）。三臂 BC-only 评测会一起出。
- 阶段 1：RL 60 updates，1×/2×/3× × s42–44，run 名 `n45_{L}_dgc_{arm}_s{seed}`：
  full_ro / full_head ← dgc_v3；lite_ro / gnnppo / nograph / gat_ours / rec_head ← dgc_noatt；mappo ← dgc_v2。共 72 个。
  顺序：主表四臂（full_ro、lite_ro、gnnppo、mappo）先。
- 阶段 2：每个 run 留出评测 `eval_heldout_n45_s1000.json`；结束 `touch /tmp/dgc_done`。
- 冒烟（4 个文件）已验证三条 BC 管线 + 评测可跑。注意：v8-noatt+forecast_off 与 v2 在 BC 阶段**数值完全相同**
  （同种子同数据 → 同权重），gnnppo 与 mappo 的差别只在 RL 阶段的 v8 代码路径。
- 判读：若 full_ro(dgc) 对 lite_ro/gnnppo/mappo(dgc) 的差距 ≥2 点且三种子一致 ⟹ 结构贡献成立；若 ≤1 点 ⟹ 优势来自 DAgger 起点，
  论文主张需改写为"训练流程（MPC-DAgger + 切换加权）"而非架构。
