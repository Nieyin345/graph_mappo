# 组会汇报：空天地一体 QKD 网络的端口受限密钥调度

2026-09-30

网络由 29 个地面站、29 个 HAP 和 30 颗低轨卫星组成（88 个节点），链路随轨道和天气时通时断。每个节点只有 1 个发送端口和 1 个接收端口，所以每个时隙能同时激活的链路必须是一个端口可行的匹配。激活的链路生成密钥，存进这条链路自己的密钥池；地面站对之间不断有带需求量和时限的请求到达，按最短可用路径、截止时间优先的规则消耗沿途各链路的库存。调度器每个时隙只决定一件事：激活哪些链路。评价指标是服务率 SR，即时限内服务的需求量占总到达量的比例。

这次汇报分三部分：我们作为基线和示教者的专家启发式，主模型的结构，以及各组对比结果。主要结论是：主模型在 4 个负载下都显著优于专家和所有图强化学习基线，负载越高优势越大，3× 负载下把专家与上界之间的差距缩小了 60%；增益主要来自链路使用预测辅助头。

## 一、专家启发式：路径贪心

### 1.1 算法

路径贪心（Path-Greedy）每个时隙运行一次，流程见图 1。

![图 1](figures/report_0930/r1_expert.png)

**图 1** 路径贪心的流程。

它先把待服务请求按截止时隙排序，逐个处理。对每个请求分三步：

1. 如果现有库存已经足以沿某条路径服务完这个请求，就跳过它，不占端口。
2. 否则为它开一条通道。先试 2 跳路径，再试 3 跳路径；每个跳数下先找"混合通道"，即路径上库存不够的链路在端口空闲时现在激活、库存够的链路直接用存量，找不到再找"新通道"，即整条路径都现在激活。一旦找到，就一次性占用这条路径需要的全部端口。
3. 所有请求都处理完后，剩下的空闲端口按链路分数贪心填满。分数由速率、中继重要性（这条链路出现在多少待服务请求的路径上，权重 10）、请求完成度、保持激活和切换代价组成，目的是为将来的请求提前攒密钥。

### 1.2 为什么用它做基线

在同一评测协议下（开发集，1× 负载，15 个种子，当时还是早期的请求分布）我们比较了 8 种启发式：

| 方法 | SR |
|---|---|
| greedy_qkp | .121 |
| random | .130 |
| greedy_matching | .189 |
| greedy_demand | .297 |
| relay_diffusion_v3 | .398 |
| greedy_rate | .490 |
| greedy_relay | .492 |
| **路径贪心** | **.767** |

路径贪心比第二名高 27 个百分点。其余方法按链路的单项指标打分，路径贪心是其中唯一一个以请求为中心、按整条路径分配端口的方法。后面所有强化学习模型都用它做行为克隆的示教者，并以它为主要对照。

### 1.3 表现与短板

路径贪心在留出集上的服务率为 .766（1×）、.740（1.5×）、.701（2×）、.629（3×），与流体 LP 上界的差距从 8.8 个百分点扩大到 18.7 个百分点。我们作为优化基线实现的滚动时域 MILP（30 时隙窗口，每 10 时隙重规划，完全预知窗口内的到达）在 1× 和 2× 下反而低于路径贪心，3× 下与它持平，所以路径贪心是一个相当强的基线。

它的短板有两点，都在后面的损失分解（3.5 节）里得到印证：

- 阶段 3 是"广撒网"。每个时隙最多可激活 88 条弧，它平均激活约 61 条，但其中只有 1.5% 在当前待服务请求的路径上，而且不区分哪些站对将来会有需求。端口被分散到很多链路上，每条链路的库存都攒不够，高负载下"库存耗尽"这一类损失占到达量的 5.5%（2×）和 8.2%（3×）。
- 计算量随规模增长很快。它要为每个请求做多轮路径搜索，88 个节点时每个时隙需要 147.5 ms，对节点数的增长斜率约为 3.3。

## 二、主模型架构

### 2.1 总体结构

![图 2](figures/report_0930/r2_arch.png)

**图 2** 主模型结构。红色虚线为链路使用预测头的训练信号与行为偏置。

模型每个时隙读入当前网络的异构图，输出一个端口可行的激活集合。它由五部分组成：边条件异构消息传递编码器、线图注意力与请求–路径注意力打分器、链路使用预测头、顺序匹配采样器和价值头。编码器由策略和价值头共享。所有参数都与节点编号无关，所以同一个模型可以直接用在节点失效或规模不同的网络上。

### 2.2 输入与编码器

图里有三类元素。节点特征 17 维，包括节点类型、相邻链路的库存与剩余容量、以该节点为源或宿的待服务量、过去 15/60/240 个时隙的到达量和时间编码。物理边特征 29 维，包括链路类型、当前与未来 6 个时隙的速率和可用性、中继重要性、上一时隙是否激活和库存剩余容量。需求边只在当前有待服务请求的站对之间建立，特征 16 维，包括待服务量、剩余时限、等待时间分桶等。

三类输入各自经过一个 MLP 投影到 128 维，再经过 3 层边条件消息传递。每层先用"邻居节点嵌入 + 边嵌入"生成消息，对物理边和需求边分别取均值后更新节点，再用两端节点的新嵌入更新边，层间用残差和 LayerNorm。需求边让请求信息可以直接在站对之间传播，去掉需求边后服务率低于专家（3.4 节）。

### 2.3 请求–路径注意力打分

每条链路用 $x_e=[h_u,h_v,e_{uv}]$ 表示。打分分两步。

第一步是线图注意力：共享端点的链路之间做 4 头注意力，输出以 0.01 的尺度初始化的残差加回去，训练开始时近似恒等。

第二步是请求–路径注意力：对每个待服务站对 $p$ 和它 4 跳以内候选路径上的每条候选弧 $a$，以"弧自身 + 站对需求嵌入"为 query，以该站对全部候选路径上的链路为 key/value 做注意力，得到弧 $a$ 在站对 $p$ 下的分数 $s_{a,p}$，再按站对权重加权平均成弧分数 $s_a$。query 里放入弧自身，是为了让同一站对内不同的候选弧得到不同的上下文；早期只用站对做 query 时，站对内各弧的分数差异只占 15%，排序能力很弱。

### 2.4 链路使用预测头

这是模型里起主要作用的部分。预测头 $g(e)$ 是一个两层 MLP，输入与弧打分器相同，预测每条链路在未来 8 个时隙内是否会"新进入"某个待服务请求的路径：

$$y_t(e)=\mathbb{1}\big[e\text{ 在 }t\text{ 时不在任何请求路径上，但在 }(t,t+8]\text{ 内出现在某个请求的路径上}\big]$$

标签在回合结束后从记录的逐时隙路径掩码回读，只依赖请求流，与策略无关。扣掉"当前已在路径上"的部分是必要的：当前在路径上的链路 100% 在接下来 8 个时隙内仍在路径上，不扣掉的话标签基本等于"现在是否在用"，而策略本来就看得到当前路径。第一版用的就是不扣掉的标签，AUC 只有 .60，还不如直接照抄当前掩码。

预测头用带正例权重的 BCE 训练（正例率约 10.6%，pos_weight 8.5），有独立的 Adam 优化器，每次 PPO 更新之前单独训练 1 个 epoch，梯度同时回传到共享编码器。训练后 AUC 约 .70–.74。此外，预测值以行为偏置的形式加到弧分数上：

$$s_a\leftarrow s_a+0.2\cdot\mathrm{zscore}\big(\tanh g(e_a)\big)$$

z-score 在图内做，偏置对策略梯度截断。第一版按未训练模型的分数标准差定了一个固定权重，训练后分数尺度放大了 100 倍，偏置等于没加，改成 z-score 后才解决。

### 2.5 顺序匹配采样器与训练

采样器在所有合法弧和一个可学习的 STOP 上做 softmax，选中一条弧后删掉与它争端口的弧（同一发端、同一收端、同一对节点的反向弧），重复直到选中 STOP 或没有可行弧。这样得到的激活集合天然满足端口约束，联合对数概率就是每一步所选项对数概率之和，可以直接用于 PPO。评测时每步取分数最高的弧，即确定性贪心解码。

训练分两步：先用路径贪心的 8 个回合做行为克隆，再做 20 次 PPO 更新（每次 8 个回合 × 240 个时隙，GAE $\gamma=0.99$、$\lambda=0.95$，clip 0.1）。单个训练用 8 个 CPU 线程，约 30–40 分钟。

### 2.6 轻量变体

把 2.3 节的两步注意力换成 $s_a=\mathrm{MLP}([h_u,h_v,e_{uv}])$，其余不变，记为"本文-无注意力"。它和 GNN-PPO 等对照共用同一个行为克隆起点，所以大部分机制实验在它上面做，保证严格单变量；跨规模迁移实验也用它。

### 3.4 消融

![图 5](figures/report_0930/r4_ablation.png)

**图 5** (a) 注意力与预测头的 2×2 析因。(b) 在轻量变体上逐项加入预测头的各部分。

**注意力 × 预测头。** 预测头在两种结构上都带来大幅提升：无注意力时 +3.9（2×）和 +6.6（3×）个百分点，有注意力时 +5.4 和 +7.9 个百分点。注意力单独加是负的（−0.9、−0.5），有预测头时变成正的（+0.6、+0.8），交互项为正。1× 和 1.5× 下有预测头时注意力的增益是 +2.0 和 +1.7 个百分点。

**预测头逐项分解。** 预测头用到的"路径近期出现次数"特征本身没有作用（−0.3、+0.2）。只训练预测头、偏置权重设为 0 时，已经拿到预测头总增益的 82%（2×）和 86%（3×）；行为偏置贡献其余部分（+0.9、+0.8，t 6.5、5.5）。完整模型上的分解结果相同（85%、85%）。也就是说，预测头主要通过辅助监督塑形共享编码器起作用，而不是在决策时提供额外信息。决策时把预测值换成真值标签或在图内随机打乱，服务率都不变（|Δ| ≤ 0.4 个百分点，不显著），也支持这一点。

### 3.5 损失分解：模型改进了哪里

把每个请求未服务的量逐时隙归因到互斥的类别（开发集种子 100–109；"本文*"为轻量变体，与 GNN-PPO 共用行为克隆起点）。

![图 7](figures/report_0930/r7_anatomy.png)

**图 7** 未服务量的构成（占到达量的百分比），柱顶数字为合计。

- 约 12% 的到达量无论怎么调度都服务不了：回合内出现过的链路全部算上，源宿站仍不连通。
- 专家几乎不浪费端口（端口空闲未激活 0.3%、0.4%），但端口分散，库存耗尽占 5.5% 和 8.2%。图强化学习学会了集中激活少数关键链路，这一类降到 2%–3%。
- 预测头相对 GNN-PPO 主要减少了端口空闲却未激活（2.7% → 1.3%，3.6% → 1.4%）、3× 下的端口冲突（7.1% → 5.8%）和库存被其他请求抢用（2.0% → 1.2%）。
- 剩余可控损失里最大的是端口冲突（4.7%、5.8%）和错过预备（3.0%、4.6%，需要时链路不可见、事前又没攒够）。

### 3.6 解码方式

顺序贪心解码可能出现这种情况：一条分数最高的弧占住两个端口，挡掉了两条分数稍低、但合计更有价值的弧。作为评测时的可选解码，我们把分数高于 STOP 的弧作为候选，以 $s_a-s_{\mathrm{STOP}}$ 为权重求端口可行的最大权匹配（二分图指派 + 对反向弧形成的 2-环做分支定界，结果精确最优），不重新训练。

| 负载 | 本文 贪心 → 最大权 | 本文-无注意力 贪心 → 最大权 | 种子为正 | 差距缩小 |
|---|---|---|---|---|
| 1× | .8028 → .8197（+1.7） | .7865 → .8148（+2.8） | 5/5 | 42% → 61% |
| 1.5× | .7877 → .8011（+1.3） | .7715 → .7943（+2.3） | 5/5 | 46% → 59% |
| 2× | .7742 → .7854（+1.1） | .7637 → .7774（+1.4） | 5/5 | 55% → 63% |
| 3× | .7411 → .7385（−0.3） | .7320 → .7336（+0.2） | 1/5 | 60% → 59% |

1×–2× 下显著提升，3× 下没有提升。2× 下端口还有余量，最大权匹配多开的链路增加了库存，端口冲突从 4.7% 降到 3.8%；3× 下端口已经饱和，端口冲突完全没有减少，这时关键是把端口给哪个请求，而分数是在顺序贪心的语义下训练出来的，分数之和不能代表这种取舍。这一解码作为可选配置保留，表 1 仍报告与训练一致的贪心解码。

### 3.8 小结与下一步

1. 主模型在所有负载下都显著优于专家、RH-MILP 和已有的图强化学习方法，3× 负载下把专家与上界之间的差距缩小 60%，88 个节点时决策时间约 9 ms。
2. 增益主要来自链路使用预测头：它给每条链路每个时隙一个稠密、与策略无关、指向请求路径的标签，其梯度塑形共享编码器，弥补了策略梯度对"提前攒密钥"这类延迟收益的信号不足。标签内容是关键，换成置换标签或信道预测标签都会造成负迁移。
3. 注意力只有在预测头存在时才有益；预测头的收益与编码器选型无关。
