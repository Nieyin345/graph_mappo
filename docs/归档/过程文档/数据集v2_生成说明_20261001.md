## 3. 流程（与论文第 III 章逐式对应）

| 步骤 | 做法 | 论文 |
|---|---|---|
| 节点 | 45 站（base = 1 的 30 站排在最前）；每站上空 20 km 一个静止 HAP；Walker 53°:30/5/1，550 km | III-A |
| 候选链路 | 全部 S–G、H–S、S–S；H–G 要求地面距离 ≤ 700 km 且仰角 ≥ α_min | 式 (1) |
| 可见性 | 地面链路 α ≥ 5°；H–S、S–S 视线最低高度 ≥ 15 km | 式 (1) |
| 透过率与本底 | `rate_model_v2.RateModelV2`（ERA5 C_n²、CAMS AOD、SMF 表、κ_x） | 式 (6)–(16)、(C1) |
| 云 | Lund–Shanklin 无云概率；每站每小时一个随机数，该站所有链路共用（seed 2023） | 式 (17) |
| 速率 | R = χ·ℓ/Δ，ℓ 为 Lim 2014 + Chernoff 的有限码长密钥长度（固定协议参数） | 式 (18)、(C2)–(C7) |
| 零链路 | 全年速率都为零的链路删除，记录在 skipped 表中 | 与旧数据集相同 |

- 有限码长函数与之前的标量参考实现在 3000 个随机点上逐比特一致。
- 轨道外推与旧生成器在 legacy 和 Walker 两种星座上一致（误差 < 1e-6）。

## 4. 冒烟对比中暴露的问题（待讨论）

数据范围：1 月 1–2 日，基础网络。专家策略的成功率只取第 1 天，所以只能看趋势。

| 指标 | 旧数据集 | 新模型 |
|---|---|---|
| 专家成功率（第 1 天） | 0.85 | 0.15 |
| H–G 每时隙可用条数 / 中位速率 | 23.4 条 / 5.2 kbps | 12.9 条 / 923 kbps |
| S–G 每时隙可用条数 / 中位速率 | 12.9 条 / 74 bps | 2.7 条 / 1.5 kbps |
| H–S 每时隙可用条数 / 中位速率 | 55.2 条 / 403 bps | 14.0 条 / 693 bps |
| S–S 每时隙可用条数 / 中位速率 | 89.6 条 / 1.1 kbps | 5.5 条 / 2.1 kbps |
| 地面站完全无可用链路的时间比例 | 0.15 | 0.56 |
| HAP 至少有一条可用星链的时间比例 | 0.70 | 0.36 |

### 不是主要原因的两项

同样 2 天、同一专家策略，只改一个因素：

- 换回旧星座：成功率 0.14。
- 换成渐近密钥率：成功率 0.17。

两者都与 0.15 差别不大。

### 主要原因（需要一起讨论）

1. **云遮挡把地面站整个切断。**
   - HAP 静止在城市正上方后，相邻 HAP 的仰角都低于 5°，每个地面站只剩自己头顶那条 H–G 链路（旧数据集的 HAP 漂移，所以有 63 条）。
   - 云按"遮挡/不遮挡"处理，阴天时这条链路和所有 S–G 链路同时断开。
2. **H–S 链路可用时间少。**
   - HAP 端是 SPAD（效率 25%）。
   - 白天平流层背景使 Y0 ≈ 5.8e-6，成码门限升到约 −35.4 dB，远距离的 H–S 链路白天基本为零。
3. **S–S 链路几乎消失。**
   - 标准 Walker 构型下，同一轨道面相邻两星相距约 6900 km，衍射损耗过大，只有异面卫星交会时短暂可用。
   - 旧星座同面卫星挤在一起、距离近，所以 S–S 很多。
4. **负载标定。**
   - 0.8 个请求/时隙 × 100 kbit 是按旧速率标定的；在新速率下可能需要重新确定。
5. **表 I 缺参数。**
   - α_min = 5°、h_min = 15 km 沿用旧代码，但表 I 中还没有列出。

以上都是模型或场景层面的决定，没有擅自修改；讨论确定后改参数重新生成即可，脚本不需要改动。
