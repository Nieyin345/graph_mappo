## 三、仍存问题（按严重度排序）

### ★ 实质问题 1：§3.2 描述的「规范」与代码实际行为不符（最重要）

**v6.7 §3.2 规定**（line 182–189）：块内**先汇总**分基/分强度计数（`n̄_b,k = p_b²p_μk Σj NjQ_μk(...)`），**再算一次** `ell`；并明确"现有数据生成器**逐 GH 节点计算有限密钥再平均**的路径**尚需对齐**本规范"。

**代码实际**（`build_dataset_v2.py:534-540, 555`）：
```python
def fk_rate(eta_arr, y0_arr, n_pulses=None):
    acc = 0.0
    for k in range(len(sc_w)):                        # 逐 Gauss–Hermite 节点
        acc += sc_w[k] * slot_rate(eta_arr*sc_h[k][_sel], y0_arr, fk, n_pulses=n_pulses)
    return acc                                        # 先逐节点算 ell，再加权求和
...
r[ok] = fk_rate(eta_c[ok], ..., n_pulses=cov_f[ok]*fk.n_pulses)   # 再乘云比例
```

即代码是 **`R = Σ_k w_k · ℓ(η·h_k·t_ci, Y0; f·N) / Δ`**（逐节点有限密钥），**不是** §3.2 的"块内汇总后算一次 ℓ"。

**判定**：v6.7 §3.2 的公式是**"目标规范/待实现"**，**不是**当前数据集的描述。v6.7 在 §3.2 末句与 §6.5 第 4 条**已诚实披露**，但：
- (a) §3.2 正文用的是**定义式语气**（`设...并满足...令...`），读者会误以为这是现状；
- (b) **两者在阈值附近数值不同**（`Σw_k·ℓ(h_k)` ≠ `ℓ(Σw_k·h_k)`，因ℓ非线性），不能假定等价。

**建议**：把 §3.2 明确分成「**当前实现**（逐 GH 节点 ℓ）」与「**目标规范**（块内汇总）」两栏，并指明**数据生成器当前走前者**。这是**最需要修**的一条。

### 问题 2：§3.2 `N_on = ⌊f_rep·Δ·d_e⌋` 在生成器里无对应实现

- v6.7 §3.2 定义 `d_e(t)=x_e[γ+(1−γ)x_e(t−1)]`，`N_on=⌊f_rep·Δ·d_e⌋`。
- **代码**：`build_dataset_v2.py` 中**完全无 γ / d_e / rate_decay**（`grep` 无结果）。γ 只在训练环境 `env.py:_generate_keys` 里 `rate *= decay` 作用。
- **含义**：数据集预计算的速率是**"满速、无 γ"**；γ 在 RL 训练时才乘。因此 §3.2 的 `N_on`（带 γ）**在数据里不成立**。
- v6.7 §6.5 第 4 条已笼统承认"环境对预计算速率乘切换因子的路径不能自动满足该规范"。

**判定**：**披露诚实**，但建议把"γ 只在 env、不在数据集"单列成**明确的一句话**（现在埋在长段落里）。

### 问题 3：§4.1 与 §0 的节点数表述易误读

- §0：主场景 **30 SAT / 45 HAP / 45 GS**。
- §4.1 表主场景行：**45 / 45 / 30**（GS/HAP/SAT）✅ 与 §0 一致。
- 但 §4.1 SAT 行文字写 **"30 颗（基础网络）/ 45 节点候选池共 30 颗"** —— "共 30 颗"紧跟"45 节点候选池"，易读成"45 颗 SAT"。

**判定**：**纯措辞**。建议改为"候选池 45 节点中含 30 颗 SAT"。

### 问题 5：§1 符号表与 §2.3.3 对上层大气消光的描述轻微不一致

- **§1**：$\Theta_S,\Theta_M$ = "采用统一气柱近似，避免重复计损"。
- **§2.3.3**：仍保留 $\Theta_S,\Theta_M=0$ 的接口说明。
- **代码**：`eta_upper()` 用 $\theta_{strat},\theta_{meso}$ 对 SAT-GS（12–50km 平流层 + 50–85km 中间层）、HAP-GS、SAT-HAP、SAT-SAT 分别算 Beer–Lambert 切层；**默认 =0 → 返回 1.0（不生效）**。

**判定**：默认不生效时**无影响**，但文档**没有描述代码里真实存在的 `eta_upper` 分层机制**（只在默认关闭状态下略过）。若未来启用 $\Theta_S/\Theta_M\neq0$，文档缺对应公式。**建议补一句**：说明代码存在上层大气切层接口、当前默认关闭。

### 问题 6：§6.3「分母为零」分支不可达（防御性，非错）
