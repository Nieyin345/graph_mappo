## 摘要

> **建模结构严谨、参数可溯源、且已被实证用于训练**——n45 主场景 108+ 个正式 run、MPC/流体 UB 参考点齐备，所以"能不能训练"**不再是待验证的问题，而是已经发生的事实**。

## 一、建模结构：无原则性错误（这一层是好的）

```
η0 = η_bp(几何衍射 × 湍流展宽 × 指向抖动) × η_clear(分子+气溶胶) × η_φ(SMF耦合) × η_tx × η_rx × η_det
R_asymp = f_rep · q_sift · [Q1(1−h2(e1)) − f_ec·Qμ·h2(Eμ)]      (GLLP 渐近诱骗态)
R_cond  = E_h[ R_asymp(η0·t_ci·h) ]                             (对数正态闪烁严格期望, GH-9)
R̄       = P_CLOS · R_cond                                       (Lund-Shanklin 云遮挡)
有限码长：Lim 2014 + Chernoff，非对称基 p_X=0.71
```

| 要素 | 评价 |
| :--- | :--- |
| 几何/湍流/指向三分量束宽 | ✅ 标准且量纲自洽（第五次审查已核） |
| 对数正态闪烁取**严格期望**（GH-9） | ✅ **优于**多数文献的"裕度+中断率"工程近似 |
| SMF 耦合用 MC 查表（非闭式） | ✅ 比闭式更准 |
| 云遮挡 Lund-Shanklin + 卷云透过 | ✅ 标准 |
| 训练/事后**双协议轨**（渐近 vs 有限码长） | ✅ 正确的工程分离 |
| 有限码长 Chernoff 界 | ✅ 比多数同类论文更严 |

**结论**：**没有一处是编造的或物理上错的**；结构层面比很多同类论文更严谨。

## 三、量级问题：**真实的、已被生成方识别的核心问题**

> 数据来源：服务器正式数据 `dataset/global_v2c`（n45 训练实际所用）+ `docs/数据集v2_生成说明_20261001.md` §4。

### 3.1 实测速率（v2c，正式数据集）

| 链路 | 正速率率 | 可见时正速率率 | 正速率均值 | 时隙均值 |
| :--- | :--- | :--- | :--- | :--- |
| HAP-GS | 85.1% | 85.1% | 622 kbps | 23.8 Mbps |
| **SAT-GS** | **0.52%** | 21.2% | **2.89 kbps** | 20.2 kbps |
| SAT-HAP | 1.40% | 25.8% | 1.41 kbps | 26.8 kbps |
| SAT-SAT | 1.26% | 9.1% | 23.2 kbps | 127 kbps |
| **全网** | — | — | — | **正速率时隙仅 2.51%** |

### 3.2 与旧模型 / Micius 的落差

生成说明 §4 的冒烟对比（第 1 天）：

| 指标 | 旧数据集 | 新模型 |
| :--- | :--- | :--- |
| 专家成功率 | 0.85 | **0.15**（后经 DAgger 起点的正式 n45 批次升到 **0.47–0.53**） |
| S–G 每时隙可用条数 / 中位速率 | 12.9 条 / 74 bps | 2.7 条 / 1.5 kbps |
| 地面站完全无可用链路的时间比例 | 0.15 | **0.56** |
| HAP 至少有星链的时间比例 | 0.70 | 0.36 |

**问题实质**：
1. **SAT-GS 2.89 kbps vs Micius 数十 kbps**——低约 1 个数量级。主因：SAT 探测效率 0.25 + $\eta_{rx}^{opt}$=0.45 + 100 Hz 暗计数 + 4 探测 + $e_d$=0.01 + $f_{ec}$=1.22 联合压制。
2. **地面站 56% 时间无可用链路**——HAP 改为"静止在城市正上方"后，相邻 HAP 仰角 <5°，每站只剩头顶那条 H–G；云按遮挡/不遮挡处理，阴天时该链路与所有 S–G 同时断开。
3. **HAP-GS 622 kbps 比 SAT-GS 高 200 倍**——策略可能退化为"躺赢 HAP"。

### 3.3 生成说明已识别的"非主因"与"主因"

**已排除**（同 2 天同专家，只改一因素）：换回旧星座 0.14、换渐近密钥率 0.17——与 0.15 差别不大 ⟹ **不是星座或协议模式导致**。

**真主因**（生成说明 §4）：云遮挡切断地面站、H–S 可用时间少、S–S 在标准 Walker 下几乎消失、负载标定未随新速率重定、表 I 缺 α_min/h_min。

> ⚠ **这些结论目前只存在于 `docs/数据集v2_生成说明_20261001.md`（一份"待讨论"备忘），未写入规范文档**。审稿人若发现规范里的硬件/几何参数会产出与 Micius 差一个数量级的速率，会直接质疑标定。

## 四、能不能作为 RL 训练数据集：**结论是"已经能，且有实证"**

### ✅ 已实证可用（不再是假设）

`docs/交接_20261003_新速率模型_n45与共同起点消融.md` 显示：

- **新模型下正式训练已完成**：n45 主场景（45 GS + 45 HAP + 30 SAT），60 updates、多种子，108+ run；
- **参考点齐备**：流体 UB 0.60–0.64、oracle_fill 0.58–0.63、MPC 0.55–0.61、专家 0.47–0.53；
- **RL 有效**：full_ro 在 DAgger 起点上 vs 专家 +.055~.061（87–92% UB）；
- 结论：**该数据集能训出有意义的调度策略**，且模型与真实结构（稀疏、昼夜、云、类型差异）一致。

### ✅ 设计上对训练友好的点

1. **归一化到位**：`graph_builder` 按链路类型归一化速率，低量级不直接压垮网络；
2. **奖励不依赖绝对速率**：`shaped` 稠密服务奖励 + 库存因果；
3. **规模合适**：2775–5625 链路 × 525600 时隙；
4. **双协议轨**：训练渐近、事后有限码长。

### ⚠ 三个前提（否则结论会被误用）

1. **目标必须是"相对调度质量"，不能是"绝对密钥产量"**。
   - 训练/评测成功率差异可测（专家 .53 vs RL .58），信号够用；
   - 但若论文声称"本系统可达 X kbps"，**不能用 Micius 实测标定**，必须用模型自洽数字。

2. **HAP 主导效应须主动检查**。
   - HAP-GS 622 kbps vs SAT-GS 2.9 kbps（200×）。建议报告**策略对链路类型的使用分布**：若几乎不用卫星，则"60/30 星星座"这个卖点在策略层面未体现——要么在奖励里平衡，要么说明"该配置下 HAP 是物理主力"（后者也是有效发现，但要讲清）。

3. **负载标定须随新速率重定**（生成说明 §4 第 4 点自己提出）。
   - 原 0.8 请求/时隙 × 100 kbit 按旧速率标定；新速率下需重估，否则"请求饥饿/溢出"比例会失真。

### ❌ 不适合的用途

1. **绝对性能外推**（"我们的调度能达多少 bps"）——量级未与实测对齐；
2. **跨论文数字直接对比**——标定不同；
3. **把训练代理当真实安全验收**——`finite_key` 目前只在事后核算，训练不闭环。

## 六、三个问题的最终回答

1. **建模有没有问题？** → **结构无原则错误、比同类更严谨**。真实问题是 **SAT-GS 绝对量级比 Micius 低约 1 个数量级** + **地面站 56% 时间无可用链路**——**标定后果，非逻辑错误**，且生成方已识别。
2. **有没有依据？** → **有**，逐参数可溯源；仅口径 0.3→0.5、探测效率 0.25 是明说的工程选择。
3. **能不能作为 RL 训练数据集？** → **能，且已被实证**（n45 主场景 108+ run 已跑完，RL vs 专家 +6 点）。前提是：**(a)** 目标定位"相对调度质量"；**(b)** 补 HAP 主导检查；**(c)** 负载标定随新速率重定；**(d)** 把量级差异写进规范文档。
