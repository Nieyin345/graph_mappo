## 二、❌ 规范文档自身的错误（规范 ↔ 代码，规范错）

### ❌ 错 1（最确凿）§2.3.1 Rayleigh 厚度 τ_R 数值错 8×

- **规范 §108**：`τ_R(P) = 0.0119 · (P/1013.25)`，称"1550 nm 下 Rayleigh 散射厚度"
- **代码**（`rate_model_v2.py:215` `rayleigh_tau()`，Hansen & Travis 1974 + Bodhaine 1999 eq.15）：
  ```python
  def rayleigh_tau(lam_um):
      return 0.008569 * lam_um**-4 * (1 + 0.0113*lam_um**-2 + 0.00013*lam_um**-4)
  ```
  1550 nm 实算 = **0.001492**
- **差**：0.0119 / 0.001492 = **7.98×**（规范多了近 1 个数量级）

**判定**：**规范写错，代码对**。`0.0119` 不是 1550nm 的 Rayleigh 厚度（更像可见光波段或混合值）。
**v6 论文的做法更稳**：只写符号 `τ_R(P)` 不给数值（v6:63），**避开了这个错**。

**影响**：若有人照规范手算，Rayleigh 项会高 8×（τ_R 与 τ_abs=0.0193 同量级相加，会导致分子消光被高估约 40%）——**只影响"照规范手算的人"，不影响代码产出的数据**。

### ❌ 错 2 §3.3 把 γ 映射到 `switch_weight` —— **两个不同机制，映射错误**

- **规范 §59 符号表 & §195**：称"RL 训练环境对应 `env_full.yaml: switch_weight: 0.001`"
- **实际**：
  - `switch_weight`（`env_full.yaml:201` = 0.001）是**奖励里的动作切换计数惩罚**：
    `R_switch = −switch_weight · N_switch`（O(1) 标量，进 reward）
  - γ（建链重对准）的**真实代码映射**是 **`env_full.yaml: switch_cost.rate_decay_factor`**（= **0.5**）：
    新激活链路本槽速率 × rate_decay_factor（进"产率"，不是 reward）

**判定**：**规范把"产率衰减因子 γ"错映射到了"奖励切换惩罚 switch_weight"**。两者是**不同的量、不同的单位、进不同的地方**。规范的 §3.3 标题"($\gamma$ 与 switch_weight)"本身就是这个混淆的产物。

### ❌ 错 3 §4.1 星座与节点数与代码/主场景不符

| 项 | 规范 §4.1 | 代码默认 | 正式主场景 |
|---|---|---|---|
| 卫星数 | **60** | `NUM_SATS=30`（walker 截断）/ `walker60`=60 | **30** |
| HAP 数 | **10** | `NUM_HAPS=30` | **45** |
| GS 数 | **30** | `NUM_GS=30` | **45** |
| 轨道高度 | **567 km** | **550 km**（`walker_delta` 默认） | 550 km |
| 倾角 | **86.4°** | **53.0°** | 53.0° |
| 星座 | Walker-delta **53:60/6/1** | **53:30/5/1**（或 opt-in `walker60`） | 53:30/5/1 |

**判定**：规范 §4.1 表 1 描述的是**一个既非代码默认、也非主场景**的构型（60/10/30 @567km/86.4°）。
- 代码**支持** `--constellation walker60`（53:60/6/1，2026-10-04 加），但**高度仍是 550 km**、**倾角 53°**，**不是 567km/86.4°**；
- 正式跑的主场景是 **45/45/30**（`scenario_n45.yaml`）。
- **三个数（60/10/30）与两个轨道参数（567/86.4）在代码里都找不到。**

> ⚠ 注意 v6 §2.3 也写了"发射高度 **567 km**"（SAT-HAP 段）——**与代码 550 km 不符**，
> 这是**规范错传染到 v6** 的证据。要么统一成 550 km，要么代码改成 567 km。

## 三、❌ §3.3 γ / g_e：**三方三样**（最需要你裁决）

| 来源 | 公式 | γ 值 | 依赖 |
|---|---|---|---|
| **规范 §193** | `g_e(t) = x_e(t)·R̄_e(t)·Δ·[γ+(1−γ)x_e(t−1)]` | **0.20** | **t−1** |
| **代码**（`env.py:_generate_keys`） | `rate ×= rate_decay_factor`（若 t−1 未激活） | `env_full`=**0.5**, `scenario_n45`=**0.0** | **t−1** |
| **v6 §104** | `g_e(t−1) = x_e(t−1)·R̄_e(t−1)·Δ·[γ+(1−γ)x_e(t−2)]` | 不给值 | **t−2** |

**三处互不相同**：
1. **规范 vs 代码**：γ 规范 0.20，代码 0.5（env_full）/ 0.0（主场景）——**值不同**；
2. **规范 vs v6**：时序 **t−1 vs t−2**——**语义不同**（v6 是"连续两槽才满速"的二步确认）；
3. **代码语义**：`rate ×= decay` 只在"t−1 未激活"时生效，**γ=decay=0 时等价"新链首槽不出码"**，是**单步**判据。

**代码实现的真身**（`env.py:354-368`）：
```python
decay = switch_cfg.get("rate_decay_factor", 0.5)   # 主场景=0.0
for edge_id in activated_edges:
    rate = edge_windows[edge_id].rates[0]
    if edge_id not in self.last_activated_edges:   # 只看 t-1
        rate *= decay
    generated[edge_id] = rate * self.scenario.slot_seconds
```

**与规范 §193 的对照**：规范写的是"首槽 20% 产率"，代码 `env_full` 是"首槽 50%"，主场景是"首槽 0%"。**规范的 0.20 在任何 config 里都没有对应值。**

**需你裁决（3 件）**：
1. **γ 取值**：0.20（规范）/ 0.5（env_full）/ 0.0（主场景）——哪个是正式论文口径？
2. **时序**：`x_e(t−1)`（规范）还是 `x_e(t−2)`（v6）？**v6 的 t−2 在规范和代码里都不存在**，疑为 v6 独有（或笔误）。
3. **规范 §195 的映射**必须改成 `switch_cost.rate_decay_factor`（见 §二.2）。

## 四、⚠️ §2.2 r0 的 (1−h/H)^{5/3} 权重

- **规范 §93** 与 **v6 §56** 都写：`r_0 = [0.423k²secζ ∫Cn²(h)(1−h/H)^{5/3}dh]^(−3/5)`
- **代码**（`rate_model_v2.py:358` `r0()`）：`integ = A*hv.c_a + hv.c_b` → **无权重** ∫Cn²dh
  （代码里带 `(h/H)^{5/3}` 权重的 `m_a/m_b` 是给 **μ_2d/长时展宽 T** 用的，:352）

**实算影响**（服务器复算）：权重使 r0 大 **2–3%** → η_φ **+9.8%（约 +0.4 dB）**。

**判定**：**规范与 v6 一致（都有权重），代码不同（无权重）**。二对一。
但因 r0 的标准定义（Fidler & Wallner 2008、Hansen-Travis 系）本就**无**这个权重，**倾向改规范+v6**。
（这与 §二.2 的"规范书写错"不同，这条是**规范说了代码没做**。）

## 七、结论

**规范文档的「物理骨架」是对的**（§2/§3 公式与代码逐条一致，这解释了为什么代码能产出自洽的数据）。
**问题都集中在「具体数值、时序语义、元数据」三类**：

1. **数值**：τ_R 写错 8×（§2.3.1）、γ 值三处不一（§3.3）；
2. **语义**：γ 的 t−1 vs v6 的 t−2；规范把 γ 错映射到 switch_weight；
3. **元数据**：§4.1 节点数/轨道（60/10/30@567km/86.4°）在代码里不存在。

**v6 论文继承了规范的部分错**（567km），**也自创了新错**（g_e 的 t−2）——即"从错的规范派生，又抄错一处"。
**代码是这三者里物理最自洽的**（τ_R 对、星座是 550km/53° 的实际值、g_e 有真实实现），**只是 γ 的默认值未与规范对齐**。

**建议**：**以代码的物理实现为准，反过来修规范与 v6**，然后**只裁决 γ 这一处**（值 + 时序），因为它同时影响 RL 训练。
