## 二、白天/夜间影响——为什么我们只有 0.5~15%，文献却有 17×

**事实**：
- 文献（Arctic 案例）：近天顶、太阳从 −37°→−13°，单光子误码 e1 从 **0.031→0.526**（17×），密钥归零。
- 我们模型：天顶 SAT-GS 的 e1 从 **0.0101→0.0102**（几乎不动），速率降 0.5%。

**为什么差这么多——两个关键差异**：

1. **波长 + 空间滤波**。文献里 e1 暴涨的是**可见/近红外（~800nm）或未做 SMF 滤波**的场景；我们固定 **1550 nm + SMF 空间滤波（etendue=3e-12）**。文献明确支持"1550nm+SMF 能把白天背景压到可用"（Nature Photonics 2017、npj QI 2021 青海湖全天候 QKD 实测背景仅 240 Hz）。**我们方向对。**

2. **但我们的天空辐亮度 `lb_day` 偏低**。我们 6.85e-5，配合 1nm 滤波 + SMF 得出的背景 ~102 Hz，虽然和青海湖 240 Hz 同量级，但**略低**。青海湖实验用的就是 1550nm+SMF，背景 240 Hz——我们的 102 Hz 是同一量级，可接受。

**判定**：白天影响小**方向正确**（1550nm+SMF 本就该这样），但**我们的模型偏"乐观"约 2 倍**（102 vs 240 Hz）。不是错，是标定偏松。

## 三、云处理——模型正确，但有一个**语义假设**要注意

### ✅ 正确的部分
- **LS_TABLE 逐字等于 Lund & Shanklin 1973 原表**（已核对 Table 16-28）；
- 公式 `P = (1-C)·C_LS(α,10C)/C_LS(90°,10C)` 正确实现；
- `C_lm = 1-(1-C_low)(1-C_mid)`（低+中云随机重叠）是标准做法；
- 卷云当衰减 `T_ci = 1 - C_hi(1-e^{-τ·m})`，τ=0.3 合理（Sassen & Cho 边界薄卷云）。

### ⚠️ 需要注意的假设：`coverage_layers` 把"云量"当成"遮挡时间比例"

代码里 `cov_f = p_clear_lund_shanklin(α, C_lm)` 然后 **`r = ... × cov_f`**（速率乘 cov_f），即把 `P_clear` 当成**该时隙可用的时间占比**（"advected cloud field: blocked fraction = coverage"）。

**这在物理上是一个假设**：它假设"云在动，1 小时内有 `C_lm` 比例的时间被挡"。而 Lund-Shanklin 原意 `P_clear` 是**某一瞬间视线无云的概率**（空间概率），不是时间比例。

- **我们的用法**：1 小时 = 60 个时隙，把 P_clear 均摊到所有时隙 ⟹ 每个时隙速率 ×P_clear，**平滑**（无 0/1 突变）。
- **传统用法**（`binary_total`）：每个时隙按 P_clear 掷骰子，**要么满速要么 0**。

**两者长期平均相同，但瞬时分布不同**。对 RL 调度，平滑版给的是"期望容量"，更适合学习；但**丢失了"这一槽到底有没有云"的信息**。这是一个**刻意的建模选择**（生成说明 §4 有记），不是 bug，但要在论文里讲清楚。

## 四、待办（需要你决定是否做）

1. **核实 `lb_day` / `lb_night` 的原始出处**（Khanna 2024 Table 1）。若 `lb_night` 真是 1.5e-5（而非我们的 1.5e-7），夜间速率会显著下降，需重标定。
   - 我倾向：`1.5e-5` 是 Cerqueti 转述的一般"夜空"值，可能含气辉；我们的 1.5e-7 是"无月晴夜@1550nm"（1550 波段夜空本就很暗）。需查 Khanna 原文定论。
2. **标定松紧**：把白天背景从 102 Hz 调到文献的 240 Hz（×2.35），看速率降幅。
3. **云语义**：是否保留 `coverage_layers`（平滑期望）还是加一个 `binary_total` 对照臂。
