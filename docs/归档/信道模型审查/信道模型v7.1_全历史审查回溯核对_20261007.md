## 二、真实遗留（未修，需你裁决或已属结果章节工作）

### 2.1 【已修，2026-10-07】builder 默认 `--channel-model` 改为 **v7**
原默认是 `v2`，不带 flag 直接跑会得到非规范数据集。**已把默认改为 `v7`**（`tools/dataset_v2/build_dataset_v2.py`），`v2` 仅作显式回退用于复现 v7 之前的数据集；docstring 与用法示例同步更新。依赖旧默认的测试已改：`test_smoke_build` 改为**不带 `--channel-model` 即走 v7 默认路径**（并断言 `k_max_first`/`rate_model=v7_finite_key`）；原 `test_coverage_cloud_model` 改写为 `test_cloud_models_coverage_vs_binary`，显式对比 v7 的 `coverage_layers` 主模型与 `binary_total` 对照（同一分层云输入）；`test_channel_no_excess` 里针对已删除的 `--kappa-x-db` CLI 的检查改为验证 v7 的 `--capture-gamma`/`--intra-slot-samples` 越界拒绝。全量 **412 passed / 4 skipped**。

### 2.2 【数值一致性，低】`f_ec` 双值：v2 遗留 `1.22` vs v7/规范 `1.16`
`tools/channel_v2/rate_model_v2.py:117 = 1.22`（仅 `skr()` 用，即 legacy v2/asymptotic 路径）；`finite_key.py:29 = 1.16`（v7 生产路径与规范）。
- **实测确认**：v7 的 `asymptotic` 路径走 `channel_v7/asymptotic_states(fk)`，用 **1.16**，**不碰** v2 的 `skr()`。故 v7 生产路径完全一致，此条只影响 legacy v2。
- **建议**：把 `rate_model_v2.py` 的 1.22 也改 1.16，或标注"legacy-only"。

### 2.3 【标定层，未做】背景噪声 Y0 敏感性（三份审查都点）
