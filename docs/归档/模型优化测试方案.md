# Hierarchical PairHist 两阶段强化学习重构方案

## 1. 背景与核心问题

当前 PairHist v3/v4 的设计主要受限于 BC（Behavior Cloning）预热需求：

\[ Score(e)=BaseScore(e)+Residual\_{Attention}(e) \]

其中 Pair Attention 作为残差模块叠加在原有 edge scorer 上。

这种设计保证了旧模型能力可以继承，但是无法回答核心研究问题：

> Pair Attention 是否能够独立学习"历史地面站对需求 →
> 量子通道形成"的能力？

同时，当前模型将两个本质不同的目标混合：

1.  当前需求通道建立；
2.  未来密钥库存准备。

两个目标共享同一个动作选择和奖励函数，导致策略无法明确区分：

-   为什么选择某条边；
-   该边服务当前请求还是未来需求。

因此提出 Hierarchical PairHist 两阶段强化学习框架。

# 3. Stage 1：需求驱动的通道构建

## 3.1 目标

Stage 1 不负责最大化密钥生成量。

核心目标：

> 根据当前和历史需求，为地面站对建立有效量子通信通道。

例如：

需求：

    GS1 <----> GS8

Stage 1 应选择：

    GS1
     |
    SAT2
     |
    SAT5
     |
    GS8

形成完整通信路径。

------------------------------------------------------------------------

# 3.2 输入信息

每个地面站对形成一个 Pair Token：

包含：

-   当前需求量；
-   请求数量；
-   等待时间；
-   deadline；
-   历史到达量；
-   历史服务量；
-   请求变化趋势。

------------------------------------------------------------------------

# 3.3 Pair Attention设计

Query：

    地面站对需求token

Key/Value：

动态物理图中的：

## 可生成边

满足：

-   当前可见；
-   当前速率大于零；
-   动作合法。

## 库存边

满足：

-   当前速率可能为零；
-   但是存在QKD密钥库存。

库存边作用：

-   表示已有通道能力；
-   帮助判断路径连通性；
-   提供已有资源状态。

------------------------------------------------------------------------

# 3.4 Stage1输出

Attention 不再输出 residual。

而是直接生成：

pair-conditioned edge score。

数学形式：

原：

\[ s_e=s\_{base}(e)+`\Delta `{=tex}s_e \]

修改：

\[ z_e=\[h_e,Attention(pair,e)\] \]

\[ s_e=MLP(z_e) \]

Attention成为第一阶段决策主体。

------------------------------------------------------------------------

# 4. Stage 1奖励设计

设计独立奖励：

\[ R_1 \]

目标：

衡量通道构建质量。

## 4.1 Path Completion Reward

如果选择边后形成完整端到端通路：

奖励。

例如：

    GS1-SAT2-SAT5-GS8

    形成完整路径

    +reward

------------------------------------------------------------------------

## 4.2 Served Demand Gain

根据选择后的实际服务提升：

\[ `\Delta `{=tex}ServedKeys \]

给予奖励。

------------------------------------------------------------------------

## 4.3 Bottleneck Reduction

如果减少需求路径瓶颈：

给予额外奖励。

------------------------------------------------------------------------

# 5. Stage 2：未来密钥准备

## 5.1 目标

Stage1解决：

当前需求。

Stage2解决：

未来需求。

输入：

Stage1未选择的候选边。

例如：

Stage1：

    选择:
    e1,e2,e3

剩余：

    e4,e5,e6

Stage2判断：

哪些边值得提前生成密钥。

------------------------------------------------------------------------

# 5.2 Stage2考虑因素

包括：

-   当前链路速率；
-   密钥库存；
-   未来速率窗口；
-   历史热点；
-   节点负载；
-   密钥过期风险。

------------------------------------------------------------------------

# 5.3 Stage2奖励

沿用当前奖励体系，并增强未来价值。

包括：

-   generated keys；
-   storage reward；
-   expired penalty；
-   future service gain。

推荐增加：

## Counterfactual Future Value

对于边 e：

比较：

选择 e 和不选择 e 的未来收益差：

\[ `\Delta `{=tex}V(e) \]

例如：

选择：

未来服务：

130M keys

不选择：

100M keys

奖励：

30M keys贡献。

这样可以明确评价：

某条备货边是否有价值。

------------------------------------------------------------------------

# 6. 两阶段训练策略

## 方案A：联合训练

整体目标：

\[ L=L_1+L_2 \]

优点：

-   端到端；
-   最终性能高。

缺点：

训练难度较高。

------------------------------------------------------------------------

# 推荐方案B：分阶段训练

## Phase 1

训练 Stage1：

目标：

学习：

历史需求 → 通道。

保存checkpoint。

------------------------------------------------------------------------

## Phase 2

冻结 Stage1：

训练 Stage2。

目标：

学习：

未来密钥准备。

------------------------------------------------------------------------

## Phase 3

联合微调：

两个阶段共同优化。

------------------------------------------------------------------------

# 7. Scratch公平实验设计

取消BC影响。

建立：

## Experiment A

Control Scratch

-   当前control模型；
-   从零训练。

## Experiment B

Hierarchical PairHist Scratch

-   Stage1 Pair Attention；
-   Stage2 Future Policy；
-   从零训练。

## Experiment C

Without Stock Edge

去除库存边输入。

验证库存信息价值。

## Experiment D

Random Pair Ablation

随机站对关系。

验证Attention是否真正利用需求结构。

------------------------------------------------------------------------

# 8. 评价指标

除了reward，需要增加：

## 8.1 Channel Completion Rate

Stage1选择边形成完整通道比例。

## 8.2 Pair Path Coverage

Attention选择边覆盖真实服务路径比例。

## 8.3 Future Provision Gain

Stage2提前准备带来的未来收益。

## 8.4 Inventory Utilization

库存边使用效率。

## 8.5 Two-stage Contribution

分别统计：

-   Stage1贡献；
-   Stage2贡献。

------------------------------------------------------------------------

# 9. 代码重构重点

修改前需要确认：

## 9.1 Graph Encoder

确认：

-   inventory edge是否进入动态图；
-   attention是否使用库存边。

## 9.2 Decoder

当前：

单阶段matching。

需要增加：

    Stage1 decoder

    +

    remove selected edges

    +

    Stage2 decoder

## 9.3 Reward Pipeline

需要支持：

分别记录：

-   当前需求收益；
-   未来准备收益。

------------------------------------------------------------------------

# 10. 预期论文贡献

最终形成：

> Hierarchical Pair-aware Reinforcement Learning for Dynamic QKD-SAGIN
> Scheduling

主要贡献：

1.  提出站对级需求感知通道构建机制；
2.  利用Pair Attention直接学习需求到物理链路映射；
3.  引入库存边增强已有量子通道感知；
4.  设计两阶段策略同时优化当前服务与未来密钥准备；
5.  通过分解奖励实现可解释的边价值评估。
