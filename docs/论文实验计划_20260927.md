## 0. 论文故事线（2026-09-27 与作者对齐后修订）

**作者目标**：RL 必须**打败专家启发式**（专家算法是作者自己写的），逼近
MILP 最优；对比其他启发式、传统算法与主流 RL；消融证明每个结构组件都有
正贡献。

**与已测事实的调和（关键）**：§10.9 已证明在**负载 1× 的资源充足 regime**
里专家吃掉天花板的 96–98%、可争空间仅 2.45% ⟹ 在该 regime "明显打败专家"
在数学上不可能，MILP 上界也会证实这一点。**能打败专家的战场是高负载 regime**：
到达率提高后端口/密钥成为真稀缺，专家的无差别撒网（98.5% 激活边与当前请求
无关）从"免费"变成"有代价"，选择性与预备才有价值。

**主图（论文核心）**：x = 负载倍率 {1, 1.5, 2, 3}×，y = success_rate，
曲线 = Random / Greedy-Rate / Greedy-Relay / **专家 Path-Greedy** /
**RL(本文)** / RH-MILP（可执行）+ MILP 松弛上界（虚线天花板）。
预期形态：1× 处大家贴上界打平（RL 以省 24–28% 密钥胜出——副图），
负载升高后 RL 与专家的 gap 拉开、且 RL 更贴近 MILP 上界。

**次效应**：负载 1× 处 RL 的密钥效率优势（已实测 24–28%，9 臂同向）——
"同等服务，密钥成本低四分之一"，作为资源充足端的卖点。

**诚实预案**：若高负载下 RL 仍不超专家（G4 门判定），回退故事 =
"效率主效应 + 天花板方法学"，v8 进 negative-result 小节。

`success_rate`、`key_efficiency`（口径统一为 **generated/served，越低越好**，

## 2. 消融实验（Ablation）

全部 3 种子起步，方向一致再补到 8（n=8 分辨力 ≈0.008 已验证）：

| # | 消融 | 对照 | 回答的问题 |
|---|---|---|---|
| A1 | v6 vs v3 | 需求边进/不进 GNN | 需求融合通道值多少（旧结论 v3>v6 +0.0084，需本节点复认） |
| A2 | v8loss vs v3 | 辅助 BCE（表示效应） | 预测任务塑形表示有没有用 |
| A3 | v8bias(z-score w∈{0.2,1}) vs v8loss | 行为偏置（决策效应） | 用预测去行动是否额外有增益 |
| A4 | v8 标签 used vs new | 标签设计 | 持续性 vs 新激活的可学性（附离线 AUC 曲线） |
| A5 | pair_path_attention arc_query on/off | 注意力粒度 | 弧级 query 的贡献（有旧数据，补本节点 3 种子） |
| A6 | reward: key-efficiency 相关项 on/off | 省钥从哪来 | 证明省钥是策略行为而非环境副产物 |

这是"优化模型结构"里性价比最高的一项，其余结构改动（LSTM 等）按 v5/v7 教训
默认不做，除非 A2/A3 出正信号。

## 3. 高负载 regime 扫描（论文主战场）

机制：**arrival_rate 倍增**（纯配置，对所有策略公平；已建
`configs/load_x15.yaml` / `load_x20.yaml` / `load_x30.yaml`，
0.8 → 1.2/1.6/2.4 请求/槽）。扫描点：负载 ∈ {1, 1.5, 2, 3}×。
每个点：全部启发式（免训练）+ 专家 + RL v3（每点**重训** 3 种子，观测分布
变了不能白嫖 1× checkpoint）+ RH-MILP + 松弛上界。
2-3 周预算下先做 {1, 2}× 两点出主图骨架，正向再补 {1.5, 3}×。

**门（G4 判定）**：2× 点上 RL−专家 配对 Δ>0 且 3/3 同向 ⟹ 故事成立，
补种子到 8 做显著性；否则触发"诚实预案"。

- 可执行 RH-MILP：窗 W、time_limit 在本节点标定（64 vCPU，HiGHS 并行）；
  目标：240 步评测一集 < 2h，`mip_gap` 全程记录，报告里注明 gap；

## 6. 执行顺序与门（每步有判据，失败早停）

1. **G0 冒烟**（~1h）：修复后代码全测试 + 1 条 20-update 训练 smoke，
   看 head_bce/head_auc 出现在 metrics.jsonl、clip_frac 正常（0.1–0.35）；
2. **G1 基线重建**（本节点）：专家/启发式/random 冻结评测（快，无训练）+
   v3 ×3 种子重训 → 与旧节点读数对齐性检查（差 >0.01 要查因）；
3. **G2 离线可学性判定**（便宜，先做）：用已录 rollout 离线监督训 new 头
   （pos_weight=8.5 + recency + 本地时间），AUC<0.65 ⟹ A3 臂降级不跑；
4. **G3 消融批次**：A1/A2/A3 并行 3 种子；A5–A7 视预算；
5. **G4 紧缺扫描**：4 个预算点 × (专家+greedy+v3×3)；
6. **G5 泛化 + MILP 列**；
7. **G6 汇总**：结果表 + 图 + 更新实验日志，论文成稿。

**预算粗估**（64 vCPU，历史吞吐折半估算）：G1 ≈ 1–2 天；G3 ≈ 2–3 天；
G4 ≈ 2 天；G2/G5 ≈ 1 天。总 ≈ 1–1.5 周机时，节点空闲即可开跑。

## 8. 场景/请求/路由合理性审查结论（2026-09-27，全代码通读后）

**审查范围**：request.py（生成）、routing.py（服务路由）、qkp.py（密钥池）、
action_resolver.py（端口模型）、reward.py。结论：**结构上无硬伤，三处需要
在论文里明说或用实验臂覆盖**：

1. **请求生成合理**：Poisson 到达 × Zipf 站对热度 × 24h 时区感知业务曲线，
   金额截断指数（max=5×mean 保证单请求可服务）、寿命 30 槽 ≈ 攒钥窗口的
   3-5 倍——量纲自洽。**但 `pair_seed: 0` 不随训练种子变** ⟹ 全部训练/评测
   共享同一组热点对。已列 held-out pair_seed 评测臂（§4），论文必须报告。
2. **服务路由是"环境固定"的**：serve 阶段走静态最短路（正存量子图 BFS
   兜底），策略只能决定"给哪些边生成密钥"，不能选路。这是刻意的问题切分
   （把调度与路由解耦），对所有策略公平、MILP 可执行模式也按同一路由建模
   ——论文里作为 problem formulation 的一部分明说即可，不是缺陷。
   注意 partial serve 取"最短正存量路"而非"最大瓶颈路"，轻度次优但
   同样对所有策略一致。
3. **端口模型（1Tx+1Rx/节点、对端不同、switch 半率惩罚）自洽**，且正是
   高负载 regime 下产生真稀缺的机制来源。1× 负载下端口余量 31% ⟹ 资源
   充足是"打不出差距"的根因（§0），不是模型缺陷。

**不修改任何场景机制**——一切改动都会作废已有测量与 BC；负载旋钮
（arrival_rate）足以制造论文需要的全部 regime。

- v8 修复后仍无效应（A2/A3 平）：故事收缩为 支柱A+B+C，v8 进 negative-result
  小节（已有完整机理链，损失可控）；
- 紧缺 regime 里 RL 需要重训才公平（观测分布变了）：每个预算点重训 v3
  （3 种子），不能拿标准 regime 的 checkpoint 白嫖；
- MILP 在紧缺点可能变难：gap 报告 + dual bound 兜底；
- 64 vCPU 吞吐不足：优先级 G1>G4>G3>G5，A5–A7 可砍。
